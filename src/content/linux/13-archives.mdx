# 压缩与归档：tar、gzip 与 zip

备份目录、传输代码、下载软件包，都绕不开 `.tar.gz`。初学者常被 tar 的参数吓到——其实只要先分清两个概念：**归档**（把多个文件打成一个包，不减体积）和**压缩**（把一个文件变小），tar 的所有用法就都顺理成章了。

## 1. 归档 ≠ 压缩

- `tar`（tape archive）只负责**归档**：把整棵目录树连同权限、时间戳打进一个 `.tar` 文件；
- `gzip` 只负责**压缩**：把**单个**文件变小，生成 `.gz`；
- 所以 Linux 世界的标准打包是两步合一：先 tar 归档、再 gzip 压缩 → `.tar.gz`（等价后缀 `.tgz`）。

这也是与 zip 的本质区别：zip 一个格式同时做两件事，而 Unix 风格是两个工具各司其职、用管道或参数组合。

## 2. tar 三大操作：c、t、x

tar 的参数看着多，主干只有三个动词（c 创建、t 查看、x 解开）加三个常用修饰（z 走 gzip、v 显示过程、f 指定文件名）：

```bash
tar czf site.tar.gz site/       # Create + gZip + File：打包压缩
tar tzf site.tar.gz             # lisT：不解开，先看包里有什么
tar xzf site.tar.gz             # eXtract：解包（还原目录树与权限）
tar xzf site.tar.gz -C /tmp     # -C：解到指定目录
```

记忆口诀：**czf 压、tzf 看、xzf 解**，f 永远紧跟文件名放最后。

<Callout type="warn" title="解包前先 tzf，防 tar 炸弹">
规范的包顶层是一个目录（如 `site/`），解开只多一个目录；不规范的包顶层直接是一堆散文件，解在当前目录会把几百个文件喷得到处都是（俗称 tar 炸弹），和已有文件混在一起极难清理。所以：解陌生的包，先 `tar tzf` 看结构，或干脆 `mkdir x && tar xzf pkg.tar.gz -C x` 隔离解包。
</Callout>

## 3. 常用进阶参数

```bash
tar czf logs.tar.gz --exclude='*.tmp' --exclude='cache' logs/   # 排除
tar czf backup-$(date +%Y%m%d).tar.gz /etc/nginx                # 文件名带日期
tar xzf big.tar.gz site/index.html                              # 只解出单个文件
tar czf - src/ | wc -c        # f 后面的 - 表示 stdout：tar 流可以进管道
```

最后一条揭示了 tar 的管道亲和性——第 19 章会看到 `tar czf - dir | ssh host 'tar xzf -'` 这种不落盘的跨机传输。

## 4. gzip 家族：单文件压缩与直读

```bash
gzip app.log             # 压缩：app.log 变成 app.log.gz（原文件消失！）
gzip -k app.log          # -k 保留原文件（GNU gzip）
gunzip app.log.gz        # 解压（等价 gzip -d）
zcat app.log.gz          # 不解压直接看内容
zgrep ERROR app.log.gz   # 不解压直接 grep——查轮转旧日志的神器
```

日志轮转（logrotate）会把旧日志压成 `access.log.1.gz`、`access.log.2.gz`……排查历史问题时，`zcat`/`zgrep` 免解压直查，配合管道无缝接入三剑客。

其他压缩格式速览：`bzip2`（更小更慢，tar 参数 j，后缀 .tar.bz2）、`xz`（压缩率最高，参数 J，.tar.xz，内核源码用它发布）、`zstd`（新一代，速度与压缩率俱佳，容器镜像层广泛使用）。tar 用法完全同构，换个字母而已。

## 5. zip / unzip：跨平台交换

与 Windows/macOS 用户交换文件时用 zip（很多精简容器需自行安装 zip/unzip 包）：

```bash
zip -r site.zip site/           # 递归打包
unzip -l site.zip               # 看内容（对应 tar tzf）
unzip site.zip -d /tmp/out      # 解到指定目录（对应 tar -C）
```

zip 与 tar.gz 的实用差异：zip 对每个文件独立压缩，可以快速抽取单个文件，但整体压缩率通常低于 tar.gz（后者把所有文件当成连续流压缩，跨文件的重复也能利用）。

## 6. 选型速查

| 场景 | 选择 |
|---|---|
| Linux 间备份/传输目录 | `tar czf`（保留权限、软链接） |
| 发给 Windows 用户 | `zip -r` |
| 查压缩的旧日志 | `zcat` / `zgrep`，不解压 |
| 追求极致压缩率（发布包） | `tar cJf`（xz） |
| 大数据量要求速度 | zstd |

## 小结

- 归档（tar 合多为一）与压缩（gzip 缩小体积）是两件事，`.tar.gz` = 两步合一
- 口诀：`czf` 压、`tzf` 看、`xzf` 解；`-C` 指定解包目录；解前先看防 tar 炸弹
- `--exclude` 排除杂物；`$(date +%Y%m%d)` 给备份命名；`f -` 让 tar 流进管道
- gzip 默认"压完删原件"；zcat/zgrep 免解压直查轮转日志
- 跨平台交换用 zip；追压缩率用 xz；追速度用 zstd

**参考答案：**

**第 1 题：打包、验证清单、解包对比**

```bash
# 构造三层目录
mkdir -p proj/src/api proj/src/web proj/docs
echo 'print(1)' > proj/src/api/main.py
echo 'hi' > proj/src/web/views.py
echo 'readme' > proj/docs/README.md

# 打包，文件名带日期

```

`diff -r` 递归对比两棵目录树，没有任何输出表示内容、权限之外的结构一致（内容层面无损）。

**第 2 题：排除 .log 和 node_modules**

```bash
mkdir -p app/node_modules app/src
echo 'debug' > app/debug.log
echo 'error' > app/error.log
echo 'dep' > app/node_modules/dep.js
echo 'code' > app/src/index.js

tar czf app.tar.gz --exclude='*.log' --exclude='node_modules' app/
tar tzf app.tar.gz
# 应只看到 app/src/index.js，.log 与 node_modules 都不在
```

`--exclude` 可写多个，模式与 `find -name` 同规则；注意排除的是**路径模式**，写成 `--exclude='node_modules'` 可匹配任意深度的同名目录。

**第 3 题：不解压操作 gzip 日志**

```bash
printf 'INFO ok\nERROR db down\nINFO recovered\n' > app.log
gzip app.log

zcat app.log.gz                        # 查看全文
zcat app.log.gz | wc -l                # 统计行数
zgrep ERROR app.log.gz                 # grep 出一行
# 若无 zgrep：zcat app.log.gz | grep ERROR
```

`zcat` 把压缩文件解到 stdout 而不落盘，所以可以任意接管道；`zgrep` 内部就是 zcat + grep。

**第 4 题：tar.gz 为什么比逐个 zip 再合并小**

```bash
# 演示：100 个相似小文件
mkdir demo && cd demo
for i in $(seq 1 100); do echo "same base content line one" > "f$i.txt"; done
cd ..

# 方式一：tar 流式压缩
tar czf all.tar.gz demo/
# 方式二：逐个 gzip 再拼包
tar cf each.tar demo/*.gz   # 先各自 gzip，再归档

ls -lh all.tar.gz each.tar
# all.tar.gz 会明显更小
```

原因：**压缩窗口（压缩算法能回溯的历史范围）可以跨越文件边界**。tar.gz 把 100 个文件当成**一个连续字节流**喂给 gzip，文件之间的重复内容（相同模板、相似头部）也能被利用压缩；而逐个 zip 时每个文件是独立压缩单元，压缩窗口在文件边界被截断，跨文件的重复无法利用，压缩率自然更低。这也是 zip"可以快速抽取单个文件"和"整体体积更大"是一体两面的原因。
