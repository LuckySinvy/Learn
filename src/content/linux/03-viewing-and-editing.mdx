# 查看与编辑文件：cat/less/head/tail 与 vim 生存指南

排查问题的第一步几乎总是"看文件"：看配置、看日志、看代码。不同大小、不同目的的文件要用不同工具——用 cat 打开 2 GB 日志会刷屏到怀疑人生。本章还包含所有人都绕不开的一课：vim 生存指南，至少保证你"进得去、改得动、出得来"。

## 1. cat：小文件一次看完

`cat`（concatenate）把文件内容一次性全部输出：

```bash
cat app.conf            # 输出整个文件
cat -n app.conf         # 带行号
cat a.txt b.txt         # 依次输出多个文件（这才是它名字"拼接"的本义）
cat a.txt b.txt > merged.txt   # 拼接并保存
```

适合**一屏能装下**的小文件：配置、脚本、hosts。反过来，大文件用 cat 会瞬间刷过几万行，毫无意义。

  title="cat 与它的伙伴们"
  id="linux-03-1"
  code={`printf 'server:\n  port: 8080\n  host: 0.0.0.0\n' > app.yaml

printf 'alpha\n\nbeta\n' > sparse.txt
echo '$ nl sparse.txt'
nl sparse.txt`}

## 2. less：大文件分页翻阅

`less` 是查看大文件的标准答案：**按需读取**，打开 10 GB 文件也是瞬间的，且支持搜索和翻页。它是交互式程序，沙箱里无法演示，常用按键务必记住：

| 按键 | 作用 |
|---|---|
| 空格 / `b` | 下翻一屏 / 上翻一屏 |
| `j` / `k` | 下移一行 / 上移一行 |
| `g` / `G` | 跳到开头 / 结尾 |
| `/关键词` | 向下搜索；`n` 下一个匹配，`N` 上一个 |
| `?关键词` | 向上搜索 |
| `F` | 追踪模式（类似 `tail -f`，Ctrl+C 退出追踪） |
| `q` | 退出 |

```bash
less /var/log/syslog        # 打开日志
less -N app.log             # 显示行号
less +G app.log             # 打开后直接跳到末尾（看最新日志）
```

<Callout type="tip" title="man 手册就是用 less 展示的">
`man ls` 打开的界面正是 less，所以上面这套按键（搜索、翻页、q 退出）在读手册时同样适用。学会 less 等于同时学会了读文档。
</Callout>

## 3. head 与 tail：只看两端

```bash
head app.log            # 前 10 行（默认）
head -n 3 app.log       # 前 3 行
head -c 100 app.log     # 前 100 字节
tail -n 5 app.log       # 最后 5 行
tail -n +3 app.log      # 从第 3 行开始输出到末尾（注意 + 号）
tail -f app.log         # 持续追踪新增内容——运维第一命令
```

<Playground
  language="linux"
  title="head / tail 精确取行"

  code={`# 生成 1..20 行的演示文件

/>

`tail -f`（follow）会保持运行、实时打印文件新追加的内容，是盯日志的标配；`tail -F` 更进一步，在日志被轮转（重命名后新建）时会自动重新打开新文件，生产环境建议用大写 F。

## 5. vim 生存指南

服务器上改配置，十有八九只有 vi/vim 可用。vim 是**模态编辑器**：同一个按键在不同模式下含义不同，这是初学者懵掉的根源。生存级理解只需要两个模式：

```text
        按 i                      按 Esc
普通模式 ────────→ 插入模式 ────────→ 普通模式
（移动/删除/命令）  （正常打字输入）
```

**最小生存流程**，背下来：

1. `vim app.conf` 打开文件，此时处于**普通模式**，打字不会输入；
2. 按 `i` 进入**插入模式**（左下角显示 INSERT），像普通编辑器一样打字；
3. 改完按 `Esc` 回到普通模式；
4. 输入 `:wq` 回车 = 保存并退出；输入 `:q!` 回车 = **不保存**强制退出。

普通模式下的少量高频操作，够用很久：

| 按键 | 作用 |
|---|---|
| `i` / `o` | 光标处插入 / 在下方新建一行并插入 |
| `dd` | 删除当前行 |
| `yy` 然后 `p` | 复制当前行、粘贴 |
| `u` | 撤销 |
| `gg` / `G` | 跳到文件开头 / 结尾 |
| `/关键词` 回车 | 搜索，`n` 跳下一个 |
| `:w` / `:q` / `:wq` / `:q!` | 保存 / 退出 / 保存退出 / 不保存强退 |

<Callout type="warn" title="被 vim 困住时的自救">
全世界每天都有人"被困在 vim 里"。万能自救三步：连按几次 `Esc`（确保回到普通模式）→ 输入 `:q!` → 回车。如果按出了奇怪状态（比如按了 Ctrl+S 导致终端"卡死"），按 Ctrl+Q 恢复。
</Callout>

<Callout type="info" title="nano：更简单的备选">
很多发行版还带 nano 编辑器：打开即可直接输入，底部明确标注快捷键（`^O` 保存、`^X` 退出，`^` 代表 Ctrl）。应急时 nano 更友好，但 vim 几乎无处不在，生存技能仍是必修。
</Callout>

## 6. 不进编辑器的快速写文件

脚本和文档里常见两种不打开编辑器就写内容的方式，后面章节会大量用到：

```bash
echo 'PORT=8080' > app.env          # 覆盖写入一行
echo 'DEBUG=true' >> app.env        # 追加一行

cat > app.conf << 'EOF'             # heredoc：一次写入多行
server {
  listen 80;
}
EOF
```

## 小结

- 小文件 `cat`（`-n` 带行号），大文件 `less`（`/` 搜索、`q` 退出），两端用 `head`/`tail`
- `tail -f` 实时追日志，轮转场景用 `tail -F`；`head | tail` 组合可取任意行区间
- `wc -l` 数行数；`file` 看真实类型，不被扩展名欺骗
- vim 生存四步：`i` 输入 → `Esc` → `:wq` 保存退出 / `:q!` 强退
- `echo >` 与 heredoc 可以不进编辑器快速写文件

<Answer>
**参考答案：**

**第 1 题：取第 42 到 45 行**

```bash
seq -f 'row %g' 100 > rows.txt
head -n 45 rows.txt | tail -n 4    # 先取前 45 行，再取其中最后 4 行
```

先 `head -n 45` 把范围压缩到 1–45 行，再用 `tail -n 4` 取出第 42–45 行。这是取任意行区间 `[A, B]` 的通用公式：`head -n B | tail -n (B-A+1)`。

**第 2 题：heredoc 创建配置 + `cat -n` 与 `nl` 对比**

```bash
cat > nginx.conf << 'EOF'
server {
  listen 80;

  location / {
    return 200;
  }
}
EOF

cat -n nginx.conf   # 每个物理行都编号，空行也占一个编号
nl nginx.conf       # 默认跳过空行，空行不编号
```

`cat -n` 对**所有行**编号（包括空行），`nl` 默认**跳过空行**不编号——所以两者行号会错开，引用行号讨论问题时要留意用哪种方式查的。

**第 3 题：vim 完整流程**

```bash
vim test.txt
# 1. 打开后处于普通模式，按 i 进入插入模式
# 2. 输入两行文字，如：hello / world
# 3. 按 Esc 回到普通模式，按 dd 删除光标所在行（第一行 hello 被删）
# 4. 按 u 撤销，被删的行恢复
# 5. 输入 :wq 回车保存退出
cat test.txt   # 应看到 hello / world 两行都在
```

如果中途想放弃修改，用 `:q!` 不保存强制退出。

**第 4 题：场景选型**

| 场景 | 命令 | 理由 |
|---|---|---|
| 8 GB 日志找关键字 | `less` + `/关键字` 搜索 | `less` 按需读取不加载全文件；`/` 搜索、`n` 跳下一个匹配 |
| 实时观察正在写入的错误日志 | `tail -f err.log`（轮转场景用 `tail -F`） | 持续打印新增内容，是盯日志的标准姿势 |
| 判断无扩展名文件是文本还是二进制 | `file 文件` | Linux 不看扩展名，`file` 通过内容特征识别 |

补充：大文件用 `cat` 会瞬间刷屏几万行，绝不能用；实时追踪也不适合反复 `cat`，而要用 `tail -f`。
</Answer>
