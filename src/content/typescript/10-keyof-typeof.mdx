# keyof、typeof 与 satisfies

前面几章我们都在**写**类型。从这一章开始，我们学习**由已有类型或已有值推导出新类型**——这是 TypeScript 类型系统真正强大的部分，也是「类型编程」的入口。

核心思路只有一句话：**不要重复定义**。类型应该从单一数据源推导出来，这样改一处就全都对上了。

## 1. keyof：取出所有键名

`keyof T` 返回 `T` 所有公开键名组成的**字符串字面量联合**：

```ts
interface User {
  id: number;
  name: string;
  active: boolean;
}

type UserKey = keyof User;    // "id" | "name" | "active"
```

它最常见的搭档就是第 9 章见过的约束：

```ts
function getProp<T, K extends keyof T>(obj: T, key: K): T[K] {
  return obj[key];
}
```

### 1.1 特殊情况

| 类型 | `keyof` 结果 |
|---|---|
| `{ a: 1; b: 2 }` | `"a" \| "b"` |
| `Record<string, number>` | `string \| number` |
| `number[]` | `number \| "length" \| "push" \| ...` 等全部数组成员名 |
| `{}` | `never` |

第二行常让人意外：索引签名为 `string` 时 `keyof` 会带上 `number`，因为 JS 里 `obj[0]` 和 `obj["0"]` 是同一个键。

## 2. typeof：从值取类型

JavaScript 里的 `typeof` 返回字符串。TypeScript 在**类型位置**复用了这个关键字，含义完全不同：**取出一个值的类型**。

```ts
const config = {
  host: "localhost",
  port: 3000,
};

type Config = typeof config;    // { host: string; port: number }
```

这是「不要重复定义」的关键工具：先写值，再由值推出类型，而不是先写类型再写一份值。

<Callout type="warn" title="两个 typeof 不要混淆">
`typeof x === "string"` 里的是**值层面**的运算符，结果是字符串；`type T = typeof x` 里的是**类型层面**的查询，结果是类型。它们只是长得一样，位置决定了含义。
</Callout>

### 2.1 keyof typeof：最常用的组合

```ts
const levels = {
  debug: 10,
  info: 20,
  error: 40,
};

type Level = keyof typeof levels;    // "debug" | "info" | "error"
```

先用 `typeof` 把值变成类型，再用 `keyof` 取键。这个组合是「用对象当枚举」这一模式的基石。

## 3. 索引访问类型

用方括号从类型里「取出」某个成员的类型，语法和访问对象属性一模一样，只是发生在类型层面：

```ts
interface User {
  id: number;
  profile: { email: string; age: number };
  tags: string[];
}

type Id = User["id"];                    // number
type Email = User["profile"]["email"];   // string，可以链式取
type Tag = User["tags"][number];         // string，用 number 取数组元素类型
```

### 3.1 三个高频技巧

1. **用联合取多个**：`User["id" | "name"]` 得到 `number | string`。
2. **用 `keyof` 取全部值类型**：`User[keyof User]` 得到所有属性类型的联合。
3. **用 `[number]` 拆数组**：`T[number]` 是「数组元素类型」的标准写法，对元组同样有效。

<Callout type="warn" title="索引访问必须用类型，不是值">
`User["id"]` 里的 `"id"` 是**字符串字面量类型**，不是字符串值。所以 `const k = "id"; type X = User[k]` 会报错——`k` 是值不是类型，得写 `User[typeof k]`。
</Callout>

## 4. as const 断言

`as const` 把一个字面量表达式「冻结」成尽可能窄的类型：

| 表达式 | 默认推断 | 加 `as const` 后 |
|---|---|---|
| `"hi"` | `string`（let） | `"hi"` |
| `[1, 2]` | `number[]` | `readonly [1, 2]` |
| `{ a: 1 }` | `{ a: number }` | `{ readonly a: 1 }` |

它做了三件事：字面量不再拓宽、数组变只读元组、对象所有属性变 `readonly`（递归生效）。

### 4.1 典型用途

```ts
const ROUTES = {
  home: "/",
  about: "/about",
} as const;

type Route = (typeof ROUTES)[keyof typeof ROUTES];   // "/" | "/about"
```

没有 `as const` 的话，`ROUTES.home` 的类型只是 `string`，`Route` 也会退化成 `string`，字面量的精度全部丢失。

## 5. satisfies 操作符

这是 TypeScript 4.9 引入的、非常实用的一个操作符。它要解决的问题是：**我想校验一个值符合某个类型，但不想让这个类型「盖住」推断出来的精确类型。**

先看没有 `satisfies` 时的两难：

```ts
type Palette = Record<string, string | [number, number, number]>;

// 方案 A：加类型注解 —— 校验有了，精度没了
const a: Palette = { red: "#f00", green: [0, 255, 0] };
// a.red 的类型是 string | [number, number, number]，不能直接 .toUpperCase()

// 方案 B：不加注解 —— 精度有了，校验没了
const b = { red: "#f00", green: [0, 255, 0] };
// 写错成 { red: 123 } 也不会报错
```

`satisfies` 同时满足两者：

```ts
const c = { red: "#f00", green: [0, 255, 0] } satisfies Palette;
// 既校验了结构，c.red 仍然是 string，c.green 仍然是 number[]
```

| 写法 | 校验值符合类型 | 保留精确推断 |
|---|---|---|
| `const x: T = ...` | 是 | 否 |
| `const x = ...` | 否 | 是 |
| `const x = ... satisfies T` | 是 | 是 |

<Callout type="tip" title="配置对象一律用 satisfies">
凡是「一个大对象，既要保证符合某个约定，又想在使用处享受精确的键名与值类型」的场景——路由表、主题色、命令注册表、i18n 词条——都是 `satisfies` 的主场。配合 `as const` 效果更佳。
</Callout>

<Callout type="warn" title="satisfies 不是 as">
`as` 是类型断言：告诉编译器「相信我，它就是这个类型」，可以指鹿为马。`satisfies` 是类型校验：让编译器检查「这个值确实符合该类型」，不符合就报错，且不改变推断结果。二者方向完全相反，`satisfies` 安全得多。
</Callout>

## 6. 一个绕不开的问题：Object.keys 为什么返回 string[]

你一定会遇到这个场景：明明知道对象只有三个键，`Object.keys(obj)` 返回的却是 `string[]`，于是 `obj[key]` 报错。

```ts
const levels = { debug: 10, info: 20 };
// Object.keys(levels).forEach((k) => console.log(levels[k]));   // 错误
```

这**不是** TypeScript 偷懒，而是结构化类型的必然结果。`levels` 的类型只描述了「至少有 debug 和 info 两个键」，运行时完全可能有更多键——比如别人传了一个结构兼容但多带了字段的对象进来。如果 `Object.keys` 声明为返回 `(keyof T)[]`，就会撒谎。

处理办法有三种，按推荐程度排列：

| 办法 | 写法 | 说明 |
|---|---|---|
| 断言键类型 | `Object.keys(o) as (keyof T)[]` | 最常用，明确表示「我知道自己在做什么」 |
| 用 `Object.entries` | `for (const [k, v] of Object.entries(o))` | 直接拿到值，绕开索引 |
| 用 `Map` | `new Map<Level, number>()` | 数据本来就是动态集合时，别用普通对象 |

<Callout type="tip" title="遇到「明明知道却报错」时先想想为什么">
TypeScript 里大部分「看起来太严格」的地方，背后都有一条站得住脚的理由。花一分钟想清楚编译器在担心什么，往往比直接加 `as any` 收获更大——有时候你会发现它担心的事情真的会发生。
</Callout>

**参考答案：**

**第 1 题：HTTP_STATUS 与两个字面量联合**

```ts
const HTTP_STATUS = {
  200: "OK",
  201: "Created",
  400: "Bad Request",
  404: "Not Found",
  500: "Internal Server Error",
} as const;

type StatusCode = keyof typeof HTTP_STATUS;
// 200 | 201 | 400 | 404 | 500   ← 注意是数字字面量，不是 string

type StatusText = (typeof HTTP_STATUS)[StatusCode];
// "OK" | "Created" | "Bad Request" | "Not Found" | "Internal Server Error"

function statusText(code: StatusCode): StatusText {
  return HTTP_STATUS[code];
}

console.log(statusText(404));   // Not Found
console.log(statusText(200));   // OK
// statusText(418);   // 错误：类型 418 的参数不能赋给类型 StatusCode 的参数

const ok: StatusText = "OK";
// const bad: StatusText = "Teapot";   // 错误：不能赋给 StatusText
console.log(ok);
```

要点：

- 如果去掉 `as const`，`HTTP_STATUS` 的值类型会被拓宽成 `string`，`StatusText` 也就退化成 `string`，字面量精度全部丢失。这正是 `as const` 存在的意义。
- `StatusText` 的推导用了本章的两个组合技：`typeof` 由值取类型，再用**索引访问 + 键名联合**一次性取出所有值类型。也可以写成更通用的 `(typeof HTTP_STATUS)[keyof typeof HTTP_STATUS]`。
- 一个容易踩的坑：`Object.keys(HTTP_STATUS)` 返回的是 `string[]`（`["200", "404", ...]`），因为 JS 对象的键在运行时永远是字符串。想拿回数字键需要转换：

```ts
const codes = Object.keys(HTTP_STATUS).map(Number) as StatusCode[];
console.log(codes.join(", "));   // 200, 201, 400, 404, 500
```

**第 2 题：pluck**

```ts
function pluck<T, K extends keyof T>(items: T[], key: K): T[K][] {
  return items.map((item) => item[key]);
}

interface Product {
  id: number;
  title: string;
  price: number;
  inStock: boolean;
}

const products: Product[] = [
  { id: 1, title: "键盘", price: 299, inStock: true },
  { id: 2, title: "鼠标", price: 99, inStock: false },
  { id: 3, title: "显示器", price: 1299, inStock: true },
];

const titles = pluck(products, "title");    // 推断为 string[]
const prices = pluck(products, "price");    // 推断为 number[]
const stocks = pluck(products, "inStock");  // 推断为 boolean[]

// 返回类型确实精确：可以直接调用各自类型的方法，无需断言
console.log(titles.map((t) => t.toUpperCase()).join("、"));  // 键盘、鼠标、显示器
console.log("总价 = " + prices.reduce((a, b) => a + b, 0));  // 总价 = 1697
console.log("有货数量 = " + stocks.filter(Boolean).length);   // 有货数量 = 2

// pluck(products, "color");   // 错误：类型 "color" 的参数不能赋给类型 keyof Product
```

要点：

- `K extends keyof T` 保证键名合法，`T[K]`（索引访问类型）保证返回的元素类型跟着键名走。两个类型参数被绑定在一起，这是本章与第 9 章共同强调的核心手法。
- 验证「类型是否精确」最直接的办法就是**去调用只有该类型才有的方法**：`titles` 能调 `.toUpperCase()` 说明它确实是 `string[]` 而不是 `unknown[]` 或 `(string | number | boolean)[]`。
- 如果签名写成 `pluck(items: T[], key: string): unknown[]`，上面三行调用全都得手动断言，泛型的价值就在这个对比里。

**第 3 题：i18n 词条与 satisfies**

```ts
const messages = {
  greeting: "你好",
  farewell: "再见",
  confirm: "确定要继续吗？",
  cancel: "取消",
} satisfies Record<string, string>;

type MessageKey = keyof typeof messages;
// "greeting" | "farewell" | "confirm" | "cancel"

function t(key: MessageKey): string {
  return messages[key];
}

console.log(t("greeting"));   // 你好
console.log(t("cancel"));     // 取消
// t("hello");   // 错误：类型 "hello" 的参数不能赋给类型 MessageKey 的参数
```

**故意写错一个值：**

```ts
const messages = {
  greeting: "你好",
  farewell: 42,          // ← 故意写成数字
  confirm: "确定要继续吗？",
} satisfies Record<string, string>;
```

报错会**精确指向 `farewell` 这一行**：

```text
TS2322: 不能将类型“number”分配给类型“string”。
  farewell: 42,
  ~~~~~~~~
```

这就是 `satisfies` 相比另外两种写法的优势：

| 写法 | 写错值时 | 键名精度 |
|---|---|---|
| `const messages = { ... }` | **不报错**，静默通过 | 精确 |
| `const messages: Record<string, string> = { ... }` | 报错，但指向整个对象 | 丢失，`keyof` 得到 `string` |
| `const messages = { ... } satisfies Record<string, string>` | 报错且**指向具体那一行** | 精确 |

第二行的问题尤其致命：一旦加了 `: Record<string, string>` 注解，`keyof typeof messages` 就变成 `string`，`t("随便写")` 也不会报错，词条 key 的拼写检查完全失效。

如果还想让每条词条的**值**也保留字面量类型（比如做类型级的文案校验），可以叠加 `as const`：

```ts
const messages = {
  greeting: "你好",
  farewell: "再见",
} as const satisfies Record<string, string>;

type Greeting = (typeof messages)["greeting"];   // "你好"，而不是 string
```

顺序是固定的：`as const` 在前，`satisfies` 在后。
</Answer>

## 小结

- `keyof T` 取键名联合，是泛型约束里最常用的搭档
- 类型位置的 `typeof` 从**值**取**类型**，`keyof typeof obj` 是标准组合拳
- 索引访问 `T[K]` 支持链式、联合下标，`T[number]` 用来取数组/元组元素类型
- `as const` 让字面量不拓宽、数组变只读元组、对象递归只读
- `satisfies` 同时做到「校验结构」与「保留精确推断」，是配置对象的最佳写法
- 记住核心原则：**从值推导类型，不要写两遍**
