# 函数类型

函数是 JavaScript 的一等公民，自然也是 TypeScript 类型系统着墨最多的地方。这一章讲怎么给函数本身标类型、怎么处理参数的各种形态，以及重载、`this`、调用签名这些进阶话题。

## 1. 给函数标类型

### 1.1 声明式函数

参数逐个注解，返回类型写在参数列表之后：

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

返回类型通常可以省略，交给推断。但**导出的函数建议显式写出**：一是作为文档，二是防止内部实现的改动悄悄改变对外契约。

### 1.2 函数类型表达式

把「函数本身」当成一个类型来描述，用箭头语法：

```ts
type BinaryOp = (a: number, b: number) => number;

const sub: BinaryOp = (a, b) => a - b;   // 参数类型由上下文推断出来
```

注意这里的 `=>` 是**类型语法**，不是箭头函数。参数名在类型里只起文档作用，可以和实现不同。

### 1.3 函数是「双向」兼容的

赋值时，参数少的函数可以赋给参数多的类型：

```ts
type Handler = (value: string, index: number) => void;
const h: Handler = (value) => console.log(value);   // 少写 index，合法
```

这符合 JS 的直觉——`arr.forEach(x => ...)` 天天这么写。反过来则不行：多要参数的函数不能赋给少给参数的类型。

## 2. 参数的四种形态

### 2.1 可选参数

```ts
function greet(name: string, title?: string): string {
  return title !== undefined ? title + " " + name : name;
}
```

`title` 的类型是 `string | undefined`，用之前必须判空。可选参数只能放在必选参数之后。

### 2.2 默认值

```ts
function repeat(text: string, times: number = 2): string {
  return text.repeat(times);
}
```

有默认值的参数自动变成可选的，而且在函数体内它的类型**不含** `undefined`（因为默认值已经兜底）。调用方显式传 `undefined` 也会触发默认值。

<Callout type="tip" title="默认值优于可选参数">
能用默认值就别用可选参数：函数体里少一次判空，调用方的心智负担也更小。默认参数还可以放在必选参数前面（虽然调用时必须显式传 `undefined`，一般不这么做）。
</Callout>

### 2.3 剩余参数

```ts
function sum(...nums: number[]): number {
  return nums.reduce((a, b) => a + b, 0);
}
```

剩余参数的类型必须是数组或元组。用**元组**类型时可以精确描述「前几个是什么、后面是什么」。

### 2.4 参数解构

```ts
function draw({ x, y, color = "red" }: { x: number; y: number; color?: string }): void {}
```

类型注解写在解构模式之后，这也是为什么解构参数的类型往往显得笨重——多数情况下会先定义一个 `interface`。

## 3. 函数重载

有些函数的参数与返回值之间存在**联动关系**，单一签名表达不了。这时可以写多个「重载签名」，再加一个兼容所有情况的「实现签名」。

```ts
function pick(v: string): string;      // 重载签名 1
function pick(v: number): number;      // 重载签名 2
function pick(v: string | number) {    // 实现签名：调用方看不见
  return v;
}
```

规则要点：

1. 实现签名**不参与**重载解析，外部只能按重载签名调用。
2. 实现签名必须**兼容**所有重载签名。
3. 解析时**从上往下**匹配第一个符合的签名，所以更具体的签名要放前面。

<Callout type="warn" title="能用联合就别用重载">
如果不同参数不会影响返回类型，`function f(x: string | number): string` 比两个重载更简单，报错信息也更友好。重载还有一个坑：它不支持「参数为联合」的调用——上面的 `pick` 不能传 `string | number` 类型的变量，因为没有任何一个重载签名能匹配。
</Callout>

## 4. this 类型

JavaScript 里 `this` 的指向取决于调用方式，是经典坑点。TypeScript 允许把 `this` 声明成**第一个形参**，它只存在于类型层面，编译后消失，也不占用实际参数位置。

```ts
interface Counter {
  count: number;
  inc(this: Counter, step: number): number;
}
```

### 4.1 箭头函数没有自己的 this

```ts
const obj = {
  count: 0,
  // 错误做法：箭头函数的 this 来自外层作用域，不是 obj
  bad: () => { /* this 不是 obj */ },
  // 正确做法：普通方法
  good(): number { return this.count; },
};
```

反过来，在回调里想保留外层 `this` 时，箭头函数正是解药。规则可以记成：**对象方法用普通函数，回调用箭头函数**。

开启 `noImplicitThis`（`strict` 已包含）后，`this` 类型无法推断的地方会直接报错，能挡下相当一部分这类问题。

## 5. 调用签名与构造签名

### 5.1 调用签名

函数在 JS 里也是对象，可以挂属性。要同时描述「能被调用」和「有哪些属性」，就得用带调用签名的对象类型：

```ts
interface Formatter {
  (value: number): string;    // 注意：没有属性名，直接是参数列表
  unit: string;
}
```

对比一下两种写法的适用场景：

| 写法 | 语法 | 能否附加属性 |
|---|---|---|
| 函数类型表达式 | `(v: number) => string` | 不能 |
| 调用签名 | `{ (v: number): string; unit: string }` | 能 |

### 5.2 构造签名

在参数列表前加 `new`，表示这个类型可以被 `new` 调用：

```ts
interface DateCtor {
  new (value: number): Date;
}
```

典型用途是工厂函数——把「类本身」当参数传进去。第 8 章讲泛型后，这个模式会变得更实用。

<Callout type="warn" title="返回类型 void 的特殊含义">
把回调声明为返回 `void`，并不意味着实现必须什么都不返回，而是「调用方承诺不使用返回值」。所以 `const fn: () => void = () => 42` 是合法的。这条规则让 `arr.forEach(x => set.add(x))` 能正常工作——`add` 有返回值，但没人关心。
</Callout>

**参考答案：**

**第 1 题：clamp 的两个版本**

版本 A —— 可选参数，函数体里必须判空：

```ts
function clamp(value: number, min?: number, max?: number): number {
  const lo = min !== undefined ? min : 0;
  const hi = max !== undefined ? max : 100;
  return Math.min(hi, Math.max(lo, value));
}
```

版本 B —— 默认参数，函数体干净得多：

```ts
function clamp(value: number, min = 0, max = 100): number {
  return Math.min(max, Math.max(min, value));
}

console.log(clamp(150));          // 100
console.log(clamp(-20));          // 0
console.log(clamp(42));           // 42
console.log(clamp(5, 10, 20));    // 10
console.log(clamp(5, undefined, 20));  // 5，显式 undefined 同样触发默认值
```

**对比：**

| | 可选参数版 | 默认参数版 |
|---|---|---|
| 函数体内 `min` 的类型 | `number \| undefined` | `number` |
| 需要判空 | 需要，每个参数一次 | 不需要 |
| 默认值写在哪 | 藏在函数体里 | 就在签名上，调用方一眼可见 |

默认参数版少了两行判空，而且**默认值成为了函数签名的一部分**——编辑器悬浮提示会直接显示 `min?: number` 及其默认值，调用方不用点进实现去猜。这就是本章「默认值优于可选参数」的具体体现。

注意 `min = 0` 不需要写 `: number`，类型会从默认值推断出来。

**第 2 题：query 重载**

```ts
interface Row {
  id: string;
  title: string;
}

const db: Record<string, string> = {
  a1: "TypeScript 手册",
  b2: "JavaScript 权威指南",
  c3: "重构",
};

function fetchOne(id: string): Row {
  return { id, title: db[id] ?? "未知条目" };
}

// 重载签名：调用方只能看到这两个
function query(id: string): Row;
function query(ids: string[]): Row[];
// 实现签名：对外不可见，必须兼容上面所有重载
function query(input: string | string[]): Row | Row[] {
  if (Array.isArray(input)) {
    return input.map(fetchOne);
  }
  return fetchOne(input);
}

const one = query("a1");          // 推断为 Row，不是 Row | Row[]
const many = query(["b2", "c3"]); // 推断为 Row[]

console.log(one.title);                     // TypeScript 手册
console.log(many.map((r) => r.title).join("、")); // JavaScript 权威指南、重构
```

要点：

- 返回类型精确到了 `Row` 或 `Row[]`，调用方**不需要再做类型收窄或断言**。这正是重载相对于「单一签名返回联合」的价值所在。
- 实现签名里用 `Array.isArray` 收窄，编译器据此确定各分支返回值合法。
- 已知的坑：变量类型是联合时调不动重载。

```ts
const key: string | string[] = Math.random() > 0.5 ? "a1" : ["b2"];
// query(key);   // 错误：没有与此调用匹配的重载
```

遇到这种情况，要么在调用处先收窄，要么额外加一条 `function query(input: string | string[]): Row | Row[];` 重载签名。

**第 3 题：带调用签名的 Memoized**

```ts
interface Memoized {
  (n: number): number;    // 调用签名：没有属性名，直接写参数列表
  cacheSize: number;      // 附加属性
}

function memoize(fn: (n: number) => number): Memoized {
  const cache = new Map<number, number>();

  const m = ((n: number): number => {
    const hit = cache.get(n);
    if (hit !== undefined) return hit;
    const value = fn(n);
    cache.set(n, value);
    m.cacheSize = cache.size;
    return value;
  }) as Memoized;

  m.cacheSize = 0;
  return m;
}

let calls = 0;
const slowSquare = (n: number): number => {
  calls++;
  return n * n;
};

const fastSquare = memoize(slowSquare);

console.log(fastSquare(4));        // 16
console.log(fastSquare(4));        // 16（这次命中缓存）
console.log(fastSquare(9));        // 81
console.log("缓存条数 = " + fastSquare.cacheSize);  // 2
console.log("真实计算次数 = " + calls);              // 2
```

要点：

- **函数类型表达式 `(n: number) => number` 无法附加属性**，必须改用带调用签名的对象类型（`interface` 或 `type` 都行）。
- 这里用了 `as Memoized` 断言：先创建一个普通函数，再补上属性。TypeScript 无法凭空知道「这个函数马上就会被加上 `cacheSize`」，所以断言在此是合理且常见的用法——注意紧接着的 `m.cacheSize = 0` 立刻兑现了断言的承诺，断言窗口非常短。
- 想避免断言，也可以用 `Object.assign`，它的返回类型是交叉类型，能被正确推断：

```ts
const m = Object.assign(wrapped, { cacheSize: 0 });   // 类型自动是函数 & { cacheSize: number }
```

## 小结

- 函数类型表达式用 `=>`；实现的参数类型可由上下文推断
- 参数少的函数可以赋给参数多的函数类型，反之不行
- 可选参数带 `undefined`，默认值参数不带；能用默认值就用默认值
- 剩余参数可以用元组类型精确描述前几位
- 重载适合「参数决定返回类型」的场景，注意实现签名对外不可见、联合参数调用不了重载
- `this` 可以声明为第一个形参，只存在于类型层面
- 调用签名让函数类型可以附带属性，构造签名描述可 `new` 的类型
