# 联合类型与类型收窄

现实世界里的值经常「可能是这个，也可能是那个」：接口返回成功或失败，参数接受字符串或数字，用户可能已登录也可能没有。**联合类型**用来描述这种「或」的关系，而**类型收窄**是把宽泛的联合一步步缩小到可安全使用的具体类型的过程。这两件事合在一起，是 TypeScript 里最能体现「类型系统理解你的代码」的部分。

## 1. 联合类型

用 `|` 把多个类型连起来：

```ts
type Id = string | number;

let id: Id = 101;
id = "A-101";      // 都可以
```

联合类型的关键规则是：**你只能访问所有成员共有的成员**。

```ts
function print(id: string | number) {
  // id.toUpperCase();   // 错误：number 上不存在 toUpperCase
  console.log(id.toString());   // 可以：两者都有 toString
}
```

这个限制不是刁难，而是必要的——编译器必须保证无论运行时拿到哪个分支的值，代码都不会崩。想用 `toUpperCase`，就得先证明它确实是字符串，这就是收窄。

<Callout type="info" title="联合是「集合的并」，成员是「能力的交」">
类型 `A | B` 的**取值范围**是 A 与 B 的并集，但它**能提供的能力**是 A 与 B 的交集。刚学时容易把方向搞反。
</Callout>

## 2. 字面量类型

具体的值本身也可以当类型：

```ts
type Direction = "up" | "down";
type Dice = 1 | 2 | 3 | 4 | 5 | 6;
type Flag = true;
```

字面量联合是 TypeScript 里最常用的「枚举替代品」：它是纯类型，不生成运行时代码，还能享受自动补全和穷尽性检查。

```ts
// 比 boolean 参数好得多，调用处一眼看懂
function setAlign(a: "left" | "center" | "right"): void {}
```

## 3. 交叉类型

`&` 表示「同时满足」，常用于组合多个对象类型：

```ts
type WithId = { id: string };
type WithTime = { createdAt: number };
type Entity = WithId & WithTime;    // 两个属性都必须有
```

| 运算 | 含义 | 对象类型上的效果 |
|---|---|---|
| `A \| B` | 是 A 或是 B | 属性取交集（只能用共有的） |
| `A & B` | 既是 A 又是 B | 属性取并集（两边的都要有） |

<Callout type="warn" title="交叉冲突会得到 never">
`{ a: string } & { a: number }` 里 `a` 的类型是 `string & number`，也就是 `never`——没有任何值能满足。编译器不会在定义处报错，只会在你试图构造这样一个对象时报错，排查起来很绕。用 `interface extends` 则会在定义处就报错。
</Callout>

## 4. 类型收窄

TypeScript 会**跟踪控制流**：在 `if` 分支内部，它知道条件已经成立，于是把变量的类型缩小。这套机制叫控制流分析（control flow analysis）。

### 4.1 typeof 收窄

适用于原始类型：

```ts
function f(x: string | number) {
  if (typeof x === "string") {
    x.toUpperCase();     // 这里 x 是 string
  } else {
    x.toFixed(2);        // 这里 x 是 number
  }
}
```

<Callout type="warn" title="typeof null 是 object">
JavaScript 的历史遗留 bug：`typeof null === "object"`。所以判断对象时不能只写 `typeof x === "object"`，必须额外排除 `null`，否则运行时会在 `null` 上访问属性而崩溃。
</Callout>

### 4.2 truthiness 真值收窄

把值直接放进条件里，会排除所有假值（`0`、`""`、`NaN`、`null`、`undefined`、`false`）：

```ts
function greet(name?: string) {
  if (name) {
    console.log(name.toUpperCase());   // name 是 string
  }
}
```

注意它把空字符串也排除了。如果只想排除 `null` / `undefined`，写 `if (name != null)` 更准确（`!=` 的宽松比较同时覆盖两者，这是少数推荐用 `!=` 的场景）。

### 4.3 相等性收窄

`===`、`!==` 以及 `switch` 都能收窄，对字面量联合尤其有效。

### 4.4 in 操作符收窄

用于区分「有没有某个属性」的对象联合：

```ts
type Fish = { swim: () => void };
type Bird = { fly: () => void };

function move(a: Fish | Bird) {
  if ("swim" in a) a.swim();
  else a.fly();
}
```

### 4.5 instanceof 收窄

用于类的实例和内置对象（`Date`、`Error`、`Array` 等）。

## 5. 可辨识联合

这是 TypeScript 里**最重要的建模模式**，没有之一。做法是：给联合中的每个成员加一个**公共的字面量属性**（叫 tag / kind / type 都行），编译器就能靠它精确区分分支。

```ts
type Circle = { kind: "circle"; radius: number };
type Square = { kind: "square"; side: number };
type Shape = Circle | Square;

function area(s: Shape): number {
  switch (s.kind) {
    case "circle": return Math.PI * s.radius ** 2;   // s 是 Circle
    case "square": return s.side ** 2;                // s 是 Square
  }
}
```

为什么它比「所有属性都可选」的写法好？对比一下：

```ts
// 反模式：无法表达「圆一定有半径」
type BadShape = { kind: string; radius?: number; side?: number };
```

后者允许构造出 `{ kind: "circle" }` 这种非法状态，每次使用都得判空。可辨识联合让**非法状态无法被表示出来**，这正是类型建模的终极目标。

配合上一章学过的 `never` 穷尽性检查，新增一个形状时编译器会精确指出所有需要更新的地方。

## 6. 类型谓词：自定义收窄

内置的收窄手段不够用时，可以写返回 `x is T` 的函数，编译器会把它当作收窄依据：

```ts
function isString(v: unknown): v is string {
  return typeof v === "string";
}
```

<Callout type="warn" title="类型谓词是一张「信任票」">
编译器不会验证 `v is string` 的函数体是否真的判断对了。如果你写错了逻辑，类型系统会跟着一起错，而且错得毫无征兆。写类型谓词时要格外小心，能用内置收窄就别自己造。
</Callout>

## 7. 收窄会在什么时候「失效」

控制流分析很聪明，但它有边界。了解这些边界能省下大量困惑的时间。

### 7.1 跨越回调边界

```ts
function f(x: string | null) {
  if (x === null) return;
  // 这里 x 是 string
  setTimeout(() => {
    // x 仍然是 string —— 因为 x 是 const 语义的参数且没被重新赋值
  }, 0);
}
```

参数没被重新赋值时，收窄能穿过闭包。但如果变量是 `let` 且在别处被赋过值，编译器就无法保证回调执行时它还是那个类型，收窄会被丢弃。**把收窄后的值存进一个 `const` 局部变量**是最简单的解法。

### 7.2 属性访问链

对 `obj.a.b` 做收窄，只对这条完整路径有效。中途调用了任何函数，编译器都会保守地认为对象可能被改过，从而作废收窄结果——尤其是可选属性配合方法调用时：

```ts
if (config.retry !== undefined) {
  doSomething();
  // config.retry 的收窄可能已失效
}
```

同样，先取出 `const retry = config.retry` 再判断即可。

### 7.3 别名判断

TypeScript 4.4 起支持「把判断结果存进 const 再用」的写法：

```ts
const isString = typeof value === "string";
if (isString) {
  value.toUpperCase();     // 4.4 起可以正确收窄
}
```

这叫**别名条件（aliased condition）**，只对 `const` 声明生效。用 `let` 存判断结果就不行。

<Callout type="tip" title="遇到收窄失效，先存成 const">
「取出到 const 局部变量」几乎能解决所有收窄失效问题，而且代码往往更清晰。这比加 `as` 断言或者非空断言 `!` 安全得多——后者是在关闭检查，前者是在帮编译器把话说清楚。
</Callout>

**参考答案：**

**第 1 题：递归 Json 类型与手写序列化**

```ts
type Json = string | number | boolean | null | Json[] | { [k: string]: Json };

function quote(s: string): string {
  return '"' + s.replace(/[\\"]/g, (m) => "\\" + m).replace(/\n/g, "\\n") + '"';
}

function stringify(v: Json): string {
  // 顺序很重要：null 必须放在最前面，因为 typeof null === "object"
  if (v === null) return "null";
  if (typeof v === "string") return quote(v);
  if (typeof v === "number") return Number.isFinite(v) ? String(v) : "null";
  if (typeof v === "boolean") return v ? "true" : "false";
  if (Array.isArray(v)) {
    return "[" + v.map(stringify).join(",") + "]";
  }
  // 走到这里，联合里只剩下索引签名对象了，编译器已自动收窄
  const body = Object.entries(v)
    .map(([k, val]) => quote(k) + ":" + stringify(val))
    .join(",");
  return "{" + body + "}";
}

const data: Json = {
  name: "Ada",
  age: 36,
  active: true,
  spouse: null,
  tags: ["math", "code"],
  address: { city: "London", zip: "N1" },
};

console.log(stringify(data));
// {"name":"Ada","age":36,"active":true,"spouse":null,"tags":["math","code"],"address":{"city":"London","zip":"N1"}}
console.log(stringify([1, "two", false, null]));
// [1,"two",false,null]
```

这道题的核心是**收窄的顺序**：

1. `v === null` 必须第一个判断。若先写 `typeof v === "object"`，`null` 会被误判成对象，随后 `Object.entries(null)` 直接抛异常。
2. `Array.isArray(v)` 是编译器认识的类型守卫，它把 `Json[]` 从联合中摘掉。
3. 前面五个分支逐一排除后，剩余类型自动收窄为索引签名对象，**不需要任何 `as` 断言**就能调用 `Object.entries`。这就是「联合类型 + 逐步收窄」的威力。
4. 递归类型是合法的：`Json` 在自己的定义里引用自己，因为引用出现在数组元素和属性值这类「延迟求值」的位置。
5. `Number.isFinite` 用来处理 `NaN` / `Infinity` —— 标准 JSON 不支持它们，原生 `JSON.stringify` 同样输出 `null`。

```ts
  | { method: "cash"; amount: number }
  | { method: "card"; last4: string; amount: number }
  | { method: "coupon"; code: string };

  throw new Error("未处理的支付方式: " + JSON.stringify(x));
}

function describe(p: Payment): string {
  switch (p.method) {
    case "cash":
      return "现金支付 " + p.amount.toFixed(2) + " 元";
    case "card":
      return "银行卡（尾号 " + p.last4 + "）支付 " + p.amount.toFixed(2) + " 元";
    case "coupon":
      return "优惠券支付，券码 " + p.code;
    default:
      return assertNever(p);
  }
}

const list: Payment[] = [
  { method: "cash", amount: 99.5 },
  { method: "card", last4: "6688", amount: 240 },
  { method: "coupon", code: "SPRING24" },
];

for (const p of list) console.log(describe(p));
// 现金支付 99.50 元
// 银行卡（尾号 6688）支付 240.00 元
// 优惠券支付，券码 SPRING24
```

注意每个 case 里能访问的属性都不一样：`p.last4` 只在 `"card"` 分支存在，在 `"cash"` 分支写 `p.last4` 会直接报错。这正是可辨识联合优于「一堆可选属性」的地方——**券码支付没有金额字段这件事，被类型系统强制表达了出来**，你不可能不小心去读一个不存在的 `amount`。

**新增一种方式后：**

```ts
type Payment =

  | { method: "card"; last4: string; amount: number }
```

## 小结

- 联合 `|` 的取值是并集，可用成员是交集；交叉 `&` 反之
- 字面量类型 + 联合是最常用的「枚举替代品」
- 收窄手段：`typeof`（原始类型）、真值判断、`===` / `switch`（字面量）、`in`（属性存在）、`instanceof`（类实例）
- `typeof null === "object"`，判断对象时必须单独排除 null
- **可辨识联合**是核心建模模式：加一个字面量 tag，让非法状态无法被表示
- 自定义类型谓词 `x is T` 很强大，但编译器不校验其正确性
