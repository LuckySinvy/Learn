# 聚合与分组

统计报表、数据大盘、运营周报——这些需求的底层全是聚合查询。本章讲透 GROUP BY 的运行模型、5.7 迁移 8.0 时最常撞上的 ONLY_FULL_GROUP_BY 报错，以及条件聚合这个实战利器。

## 1. 聚合函数

| 函数 | 作用 | 对 NULL 的处理 |
|---|---|---|
| COUNT(*) | 统计行数 | 计入所有行 |
| COUNT(col) | 统计 col 非 NULL 的行数 | 跳过 NULL |
| SUM(col) | 求和 | 跳过 NULL |
| AVG(col) | 平均值 | 跳过 NULL（分母是非 NULL 行数） |
| MAX / MIN | 最大/最小 | 跳过 NULL |
| GROUP_CONCAT(col) | 组内拼接字符串 | 跳过 NULL |

<Playground
  language="mysql"
  id="mysql-08-1"
  title="常用聚合函数"
  code={`SELECT COUNT(*)            AS order_count,
       SUM(total_amount)   AS gmv,
       AVG(total_amount)   AS avg_amount,
       MAX(total_amount)   AS max_amount,
       MIN(created_at)     AS first_order_time
FROM orders
WHERE status IN (1, 2, 3);`}
/>

两个易错点：

- **AVG 跳过 NULL**：`AVG(score)` 的分母是非 NULL 行数。想把 NULL 当 0 算：`AVG(IFNULL(score, 0))`，两者业务含义完全不同，先想清楚要哪个。
- **空结果集**：无分组聚合永远返回一行，`SUM` 对空集返回 NULL 而不是 0，程序侧记得 `IFNULL(SUM(x), 0)`。

## 2. GROUP BY 分组

GROUP BY 的运行模型：**按分组列把行分堆，每堆坍缩成一行输出**，聚合函数在每堆内部计算。

<Playground
  language="mysql"
  id="mysql-08-2"
  title="GROUP BY：单列、多列与表达式分组"
  code={`-- 每个用户的订单数与消费总额
SELECT user_id,
       COUNT(*)          AS order_count,
       SUM(total_amount) AS total_spent
FROM orders
GROUP BY user_id;

-- 多列分组按「列组合」分堆
SELECT user_id, status, COUNT(*) AS cnt
FROM orders
GROUP BY user_id, status;

-- 按表达式分组（日报表的标准写法）
SELECT DATE(created_at)  AS order_date,
       COUNT(*)          AS order_count,
       SUM(total_amount) AS daily_gmv
FROM orders
GROUP BY DATE(created_at)
ORDER BY order_date;`}
/>

## 3. ONLY_FULL_GROUP_BY：8.0 的严格模式

思考这条 SQL 有什么问题：

```sql
SELECT user_id, order_no, COUNT(*)
FROM orders
GROUP BY user_id;
```

每个 user_id 分组里有多条订单，`order_no` 该显示哪一条的？逻辑上没有答案。5.7 默认会**随机返回组内某一行的值**（结果不确定却不报错，坑了无数人）；8.0 默认开启 `ONLY_FULL_GROUP_BY`，直接报错：

```text
ERROR 1055 (42000): Expression #2 of SELECT list is not in GROUP BY clause
and contains nonaggregated column 'shop.orders.order_no' ...
```

规则：**SELECT 里的每一列，要么出现在 GROUP BY 里，要么被聚合函数包住**。三种正确的改法：

```sql
-- 1. 你要的其实是聚合值
SELECT user_id, COUNT(*), MAX(order_no) FROM orders GROUP BY user_id;

-- 2. 你要的是「每组任取一个」，显式表达出来
SELECT user_id, ANY_VALUE(order_no), COUNT(*) FROM orders GROUP BY user_id;

-- 3. 你要的是「每组最新的一条完整行」→ 这是 Top-N 问题，用窗口函数（第 11 章）
```

<Callout type="warn" title="不要通过关闭 ONLY_FULL_GROUP_BY 来消除报错">
把 sql_mode 里的 ONLY_FULL_GROUP_BY 去掉确实能让老 SQL 跑起来，但那只是把「确定的报错」换成「不确定的结果」。正确做法是逐条修正 SQL 语义。
</Callout>

## 4. HAVING：过滤分组

WHERE 在**分组前**过滤行，HAVING 在**分组后**过滤组：

<Playground
  language="mysql"
  id="mysql-08-3"
  title="WHERE 分组前过滤，HAVING 分组后过滤"
  code={`-- 消费总额超过 5000 的用户（只统计已支付以上状态）
SELECT user_id, SUM(total_amount) AS total_spent
FROM orders
WHERE status IN (1, 2, 3)          -- 分组前：过滤行
GROUP BY user_id
HAVING SUM(total_amount) > 5000    -- 分组后：过滤组
ORDER BY total_spent DESC;`}
/>

原则：**能写进 WHERE 的条件绝不放 HAVING**。WHERE 先减少参与分组的行数，还能利用索引；HAVING 是对分组结果的兜底过滤，只放必须依赖聚合值的条件。

完整的逻辑执行顺序（和书写顺序不同，理解它能解释很多「为什么报错」）：

```text
FROM → WHERE → GROUP BY → 聚合 → HAVING → SELECT → ORDER BY → LIMIT
```

这也解释了：WHERE 里不能用聚合函数（还没算出来）、WHERE 里不能用 SELECT 别名（SELECT 还没执行），而 ORDER BY 可以用别名。

## 5. 条件聚合：一条 SQL 出多指标

CASE 塞进聚合函数，是报表 SQL 的核心技巧：

<Playground
  language="mysql"
  id="mysql-08-4"
  title="条件聚合：一条 SQL 出多指标"
  code={`SELECT DATE(created_at) AS d,
       COUNT(*)                                    AS total_orders,
       SUM(CASE WHEN status = 4 THEN 1 ELSE 0 END) AS cancelled,
       SUM(CASE WHEN status IN (1,2,3)
                THEN total_amount ELSE 0 END)      AS paid_gmv,
       SUM(status = 4) / COUNT(*)                  AS cancel_rate
FROM orders
GROUP BY DATE(created_at)
ORDER BY d;`}
/>

`SUM(status = 4)` 是 MySQL 特有的简写：布尔表达式结果是 0/1，SUM 就是满足条件的行数（等价于 `COUNT(IF(status=4, 1, NULL))`）。一条 SQL 同时算出总单量、取消量、支付 GMV、取消率——不需要跑四次查询。

## 6. WITH ROLLUP：自动加小计

```sql
SELECT user_id, status, COUNT(*) AS cnt, SUM(total_amount) AS amount
FROM orders
GROUP BY user_id, status WITH ROLLUP;
```

```text
+---------+--------+-----+----------+
| user_id | status | cnt | amount   |
+---------+--------+-----+----------+
|       1 |      0 |   1 |   177.00 |
|       1 |      3 |   1 |  8127.00 |
|       1 |   NULL |   2 |  8304.00 |   ← user_id=1 的小计
|       2 |      1 |   1 |  3999.00 |
|       2 |   NULL |   1 |  3999.00 |
|       3 |      4 |   1 |  8999.00 |
|       3 |   NULL |   1 |  8999.00 |
|    NULL |   NULL |   4 | 21302.00 |   ← 总计
+---------+--------+-----+----------+
```

ROLLUP 按分组列从右往左逐层汇总，小计行的分组列显示 NULL。用 `GROUPING(col)` 可以区分「小计产生的 NULL」和「数据本身的 NULL」：

```sql
SELECT IF(GROUPING(user_id), '总计', user_id) AS u,
       IF(GROUPING(status),  '小计', status)  AS s,
       COUNT(*) AS cnt
FROM orders
GROUP BY user_id, status WITH ROLLUP;
```

## 小结

- COUNT(*) 数行、COUNT(col) 数非 NULL；SUM 对空集返回 NULL 记得 IFNULL
- GROUP BY 把行分堆坍缩，SELECT 列必须「在分组里或被聚合」（ONLY_FULL_GROUP_BY）
- WHERE 分组前过滤、HAVING 分组后过滤，条件能前置就前置
- 条件聚合 `SUM(CASE WHEN ...)` 一条 SQL 出全部指标
- WITH ROLLUP 免费得到小计与总计

<Answer>
**参考答案：**

**1. 分类维度统计 + HAVING 过滤**

```sql
SELECT c.id,
       c.name                    AS category_name,
       COUNT(*)                  AS product_count,
       ROUND(AVG(p.price), 2)    AS avg_price,
       MAX(p.price)              AS max_price
FROM products p
JOIN categories c ON c.id = p.category_id
GROUP BY c.id, c.name
HAVING COUNT(*) >= 2
ORDER BY product_count DESC, avg_price DESC;
```

只用 products 表（不带分类名）的简化版：

```sql
SELECT category_id,
       COUNT(*)               AS product_count,
       ROUND(AVG(price), 2)   AS avg_price,
       MAX(price)             AS max_price
FROM products
GROUP BY category_id
HAVING COUNT(*) >= 2;
```

要点：

- 过滤条件 `COUNT(*) >= 2` **依赖聚合结果，只能放 HAVING**，写进 WHERE 会报 `Invalid use of group function`——因为逻辑执行顺序是 `FROM → WHERE → GROUP BY → 聚合 → HAVING`，WHERE 执行时聚合值还不存在。
- 反过来，像「只统计在售商品」这种不依赖聚合的条件**必须前置到 WHERE**，让它先减少参与分组的行数并利用索引：

```sql
WHERE p.status = 1
GROUP BY c.id, c.name
HAVING COUNT(*) >= 2
```

- `GROUP BY c.id, c.name` 把 `c.name` 也带上是为了满足 ONLY_FULL_GROUP_BY。严格说 `c.id` 是主键、`c.name` 函数依赖于它，MySQL 8.0 能识别这种函数依赖并允许只写 `GROUP BY c.id`，但显式列全更通用、跨数据库也安全。
- `AVG` 返回的小数位很长，用 `ROUND(x, 2)` 修饰。

**2. 条件聚合出多指标**

```sql
SELECT DATE(created_at)                              AS d,
       COUNT(*)                                      AS total_orders,
       SUM(status = 3)                               AS completed,
       SUM(status = 4)                               AS cancelled,
       ROUND(SUM(status = 4) / COUNT(*) * 100, 2)    AS cancel_rate_pct
FROM orders
GROUP BY DATE(created_at)
ORDER BY d;
```

等价的标准 CASE 写法（可移植到其他数据库）：

```sql
SELECT DATE(created_at) AS d,
       COUNT(*)                                          AS total_orders,
       SUM(CASE WHEN status = 3 THEN 1 ELSE 0 END)       AS completed,
       SUM(CASE WHEN status = 4 THEN 1 ELSE 0 END)       AS cancelled,
       ROUND(
         SUM(CASE WHEN status = 4 THEN 1 ELSE 0 END) / COUNT(*) * 100,
       2)                                                AS cancel_rate_pct
FROM orders
GROUP BY DATE(created_at)
ORDER BY d;
```

要点：

- `SUM(status = 4)` 利用了 MySQL 布尔表达式返回 0/1 的特性，是 `SUM(CASE WHEN status = 4 THEN 1 ELSE 0 END)` 的简写，也等价于 `COUNT(IF(status = 4, 1, NULL))`。
- **不能写成 `COUNT(status = 4)`**：`status = 4` 无论真假都是非 NULL 值（1 或 0），COUNT 会把所有行都数进去，结果恒等于总行数。
- `COUNT(*)` 作为分母永远不为 0（能进分组说明至少有 1 行），所以这里不需要防除零。但如果分母是 `SUM(某条件)`，就要用 `NULLIF(x, 0)` 保护。
- 条件聚合的核心价值：**一次扫表出全部指标**。如果拆成四条 SQL 分别统计，就要扫四遍表。

**3. 触发并修正 ONLY_FULL_GROUP_BY**

```sql
-- 触发 1055
SELECT user_id, order_no, COUNT(*) AS cnt
FROM orders
GROUP BY user_id;
```

```text
ERROR 1055 (42000): Expression #2 of SELECT list is not in GROUP BY clause
and contains nonaggregated column 'shop.orders.order_no' which is not
functionally dependent on columns in GROUP BY clause; this is incompatible
with sql_mode=only_full_group_by
```

**修法 A：用聚合函数——语义明确**

```sql
SELECT user_id, MAX(order_no) AS max_order_no, COUNT(*) AS cnt
FROM orders
GROUP BY user_id;
```

**修法 B：用 ANY_VALUE——语义是「随便给一个」**

```sql
SELECT user_id, ANY_VALUE(order_no) AS some_order_no, COUNT(*) AS cnt
FROM orders
GROUP BY user_id;
```

**两者语义差异（这是本题的重点）：**

| | `MAX(order_no)` | `ANY_VALUE(order_no)` |
|---|---|---|
| 返回什么 | 组内 order_no 的**字典序最大值**，确定且可复现 | 组内**任意一行**的值，由执行计划决定 |
| 多次执行 | 结果稳定 | 结果**可能不同**（换索引、改并行度都会变） |
| 本质 | 真正的聚合计算 | 告诉优化器「我知道这不确定，别报错」 |
| 适用 | 你确实要最大/最小值 | 该列在组内**本来就唯一**（如按 user_id 分组取 username） |

`ANY_VALUE` 只是**抑制检查**，不做任何计算，所以它是一个「承诺」：你向 MySQL 保证这个列在组内取哪个都无所谓。合理场景是列与分组键一一对应：

```sql
-- username 与 user_id 一一对应，取哪行都一样
SELECT u.id, ANY_VALUE(u.username) AS username, COUNT(o.id) AS order_cnt
FROM users u LEFT JOIN orders o ON o.user_id = u.id
GROUP BY u.id;
```

**如果真正想要的是「每组最新的一条完整订单」**，上面两种都不对——`MAX(order_no)` 和其他列不保证来自同一行（这是「聚合错行」经典陷阱）。这属于 Top-N per group 问题，要用窗口函数（第 11 章）：

```sql
SELECT user_id, order_no, total_amount, created_at
FROM (
  SELECT user_id, order_no, total_amount, created_at,
         ROW_NUMBER() OVER (PARTITION BY user_id ORDER BY created_at DESC) AS rn
  FROM orders
) t
WHERE rn = 1;
```

最后再强调：**绝不要通过关闭 `ONLY_FULL_GROUP_BY` 来消除 1055**。那只是把「明确的报错」换成「静默的错误结果」，5.7 升 8.0 时暴露出的这批 SQL，恰恰是过去一直在返回不确定数据的隐患。
</Answer>
