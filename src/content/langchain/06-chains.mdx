# 链 Chains

**Chain（链）** 把「提示模板 → 模型 → 解析器」等组件按顺序串起来，封装成一个可整体调用的单元。在 LCEL 普及前，`LLMChain` 是主要写法；现在推荐用 LCEL（第 7 章），但理解 Chain 有助于维护老代码。

## 1. LLMChain（经典写法）

```ts
import { LLMChain } from "langchain/chains";
import { ChatOpenAI } from "@langchain/openai";
import { ChatPromptTemplate } from "@langchain/core/prompts";

const llm = new ChatOpenAI({ model: "gpt-4o-mini" });
const prompt = ChatPromptTemplate.fromTemplate(
  "把下面句子翻译成英文：\n{sentence}"
);

const chain = new LLMChain({ llm, prompt });
const res = await chain.call({ sentence: "今天天气真好" });
console.log(res.text);
```

<Callout type="info" title="LLMChain 的局限">
它只封装「单提示 + 单模型 + 文本输出」这一固定形状，难以表达分支、并行、回退。新项目直接用 LCEL 的 `pipe` 更灵活。
</Callout>

## 2. SequentialChain：串联多步

需要「上一步输出作为下一步输入」时，用 `SequentialChain`：

```ts
import { SequentialChain, LLMChain } from "langchain/chains";

// 第一步：生成大纲
const outlineChain = new LLMChain({
  llm,
  prompt: ChatPromptTemplate.fromTemplate("为《{topic}》写三条要点"),
  outputKey: "outline",
});

// 第二步：根据大纲扩写
const expandChain = new LLMChain({
  llm,
  prompt: ChatPromptTemplate.fromTemplate("根据要点扩写：{outline}"),
  outputKey: "essay",
});

const overall = new SequentialChain({
  chains: [outlineChain, expandChain],
  inputVariables: ["topic"],
  outputVariables: ["essay"],
});

const result = await overall.call({ topic: "向量数据库" });
console.log(result.essay);
```

## 3. 用 LCEL 等价重写

上面的顺序链用 LCEL 一行就能表达，且天然支持流式与并行：

```ts
import { RunnableSequence } from "@langchain/core/runnables";

const chain = RunnableSequence.from([
  ChatPromptTemplate.fromTemplate("为《{topic}》写三条要点"),
  llm,
  new StringOutputParser(),
  // 再接一个「扩写」子链……
]);
```

<Callout type="tip" title="新项目用 LCEL">
`RunnableSequence.from([...])` 可读性更好，且默认具备 `.stream()`、`.batch()`、`.withConfig()` 等能力，无需额外封装。
</Callout>

## 4. 选型建议

| 需求 | 推荐 |
|---|---|
| 单提示模板 + 模型 | `prompt.pipe(model)` |
| 多步顺序 | `RunnableSequence` |
| 维护旧代码 | `LLMChain` / `SequentialChain` 仍可运行 |

<Callout type="exercise" title="练习">
把「翻译 → 润色」两步走用 `RunnableSequence` 重写，并试着对最终结果调用 `.stream()`。

<Answer>
**参考答案：**

**完整实现**

关键在于：第一步的输出是**字符串**，而第二步的提示模板需要一个**对象**（键名要对上 `{draft}`）。中间用一个普通函数做转换即可——任何函数都能作为 LCEL 的一环。

```ts
import "dotenv/config";
import { ChatOpenAI } from "@langchain/openai";
import { ChatPromptTemplate } from "@langchain/core/prompts";
import { StringOutputParser } from "@langchain/core/output_parsers";
import { RunnableSequence } from "@langchain/core/runnables";

const llm = new ChatOpenAI({ model: "gpt-4o-mini", temperature: 0.3 });
const parser = new StringOutputParser();

// 第一步：直译
const translatePrompt = ChatPromptTemplate.fromTemplate(
  "把下面的中文忠实翻译成英文，只输出译文：\n{sentence}"
);

// 第二步：润色
const polishPrompt = ChatPromptTemplate.fromTemplate(
  "下面是一段机器翻译的英文。请把它润色得更地道、更符合母语者习惯，只输出润色后的结果：\n{draft}"
);

const chain = RunnableSequence.from([
  translatePrompt,
  llm,
  parser,
  // 承上启下：string → { draft: string }
  (draft: string) => ({ draft }),
  polishPrompt,
  llm,
  parser,
]);

const result = await chain.invoke({ sentence: "今天天气真好，我们出去走走吧。" });
console.log(result);
```

**对最终结果流式输出**

`RunnableSequence` 的 `.stream()` 会自动把**最后一环**的输出逐块吐出来。因为末尾接的是 `StringOutputParser`，拿到的直接是字符串片段：

```ts
const stream = await chain.stream({ sentence: "今天天气真好，我们出去走走吧。" });

for await (const chunk of stream) {
  process.stdout.write(chunk);   // 逐字打印润色结果
}
console.log();
```

**流式的边界在哪**：这里只有**第二步（润色）**是逐字流出的。第一步翻译必须完整生成后才能作为第二步的输入，所以你会看到「先停顿几秒，然后突然开始逐字输出」。这是顺序链的固有特性，不是 bug。

**改进一：用 `RunnableLambda` 让转换步骤可命名可追踪**

直接传函数最简洁，但在 LangSmith 里会显示成匿名节点。想让链路更可读，用 `RunnableLambda` 包一层：

```ts
import { RunnableLambda } from "@langchain/core/runnables";

const toDraft = RunnableLambda.from((draft: string) => ({ draft }))
  .withConfig({ runName: "拼装润色输入" });
```

**改进二：同时拿到译文和润色稿**

上面的链只返回最终结果，中间的直译稿丢了。如果想对比两版，用 `RunnableMap` 把原文带下去：

```ts
import { RunnableMap } from "@langchain/core/runnables";

const chainWithBoth = RunnableSequence.from([
  translatePrompt,
  llm,
  parser,
  RunnableMap.from({
    draft: (d: string) => d,                              // 原样保留直译
    polished: RunnableLambda.from((d: string) => ({ draft: d }))
      .pipe(polishPrompt)
      .pipe(llm)
      .pipe(parser),
  }),
]);

const out = await chainWithBoth.invoke({ sentence: "今天天气真好，我们出去走走吧。" });
console.log("直译：", out.draft);
console.log("润色：", out.polished);
```

注意这种写法下 `.stream()` 拿到的是**逐步累积的对象补丁**而非字符串，前端消费方式要相应调整。

**改进三：加容错**

给模型加回退，主模型挂了自动切备用（第 7 章会详解）：

```ts
const robustLlm = llm.withFallbacks({
  fallbacks: [new ChatOpenAI({ model: "gpt-4o" })],
});
```

**与 `SequentialChain` 的对比**

| | `SequentialChain` | `RunnableSequence` |
|---|---|---|
| 传值方式 | 靠 `outputKey` 字符串约定，写错了运行时才发现 | 上一环返回什么，下一环就收什么，TS 能推断 |
| 流式 | 不支持 | `.stream()` 开箱即用 |
| 批处理 | 需自己写循环 | `.batch([...])` 自动并发 |
| 插入自定义逻辑 | 要包成一个 Chain 类 | 直接塞一个箭头函数 |

这也是课文建议「新项目直接用 LCEL」的原因——本题里那个 `(draft) => ({ draft })` 转换，用 `SequentialChain` 需要额外定义 `outputKey` 并保证下游 `inputVariables` 完全匹配，反而更绕。
</Answer>

## 小结

- `LLMChain` 是经典单步封装，现已推荐用 LCEL 替代
- `SequentialChain` 串联多步，上一步 `outputKey` 作为下一步输入
- 新代码优先 `RunnableSequence.from([...])`
