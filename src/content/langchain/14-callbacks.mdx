# 回调与可观测性 Callbacks

当链变长、Agent 多步调用时，你一定想知道：「每一步花了多久？用了多少 Token？哪一步报错了？」**Callbacks（回调）** 就是 Langchain.js 的「事件钩子」机制。

## 1. 自定义 CallbackHandler

继承 `BaseCallbackHandler`，重写你关心的事件方法：

```ts
import { BaseCallbackHandler } from "@langchain/core/callbacks/base";

class LogHandler extends BaseCallbackHandler {
  name = "LogHandler";

  async handleLLMStart(llm, prompts) {
    console.log("▶ 模型开始，prompt 长度:", prompts[0].length);
  }
  async handleLLMEnd(output) {
    const tokens = output.llmOutput?.usage?.total_tokens;
    console.log("■ 模型结束，Token:", tokens);
  }
  async handleChainError(err) {
    console.error("✗ 链报错:", err.message);
  }
}

// 挂到调用上
await chain.invoke(input, { callbacks: [new LogHandler()] });
```

<Callout type="info" title="常用事件">
`handleLLMStart/End`、`handleChainStart/End`、`handleToolStart/End`、`handleRetrieverStart/End`——几乎每个组件都有 start/end/error 三件套。
</Callout>

## 2. 全局 vs 局部回调

```ts
// 全局：所有调用生效
import { configureCallbacks } from "@langchain/core/callbacks";
// 或在构造模型时传 callbacks

// 局部：仅本次生效（推荐，影响最小）
await chain.invoke(input, { callbacks: [handler] });
```

## 3. 接入 LangSmith

LangSmith 是官方可观测性平台，靠回调自动上报每一次调用链路：

```bash
npm install langsmith
```

```bash
# .env
LANGCHAIN_TRACING_V2=true
LANGCHAIN_API_KEY=lsv2_xxxxxxxx
LANGCHAIN_PROJECT=my-langchain-app
```

```ts
import "dotenv/config";
// 配置好环境变量后，无需改业务代码，
// 所有 invoke/stream 会自动上报到 LangSmith 控制台
await chain.invoke({ question: "什么是 RAG？" });
```

<Callout type="tip" title="为什么值得接">
LangSmith 帮你可视化「提示词 → 模型 → 工具 → 检索」的完整瀑布图，逐层看 Token、耗时、输入输出，是调试 Agent 与 RAG 的利器。
</Callout>

## 4. 典型用途

| 用途 | 做法 |
|---|---|
| 计费/审计 | `handleLLMEnd` 累加 Token |
| 性能监控 | 记录每步耗时，定位慢环节 |
| 日志告警 | `handleChainError` 上报错误 |
| 调试 | LangSmith 全链路回放 |

<Callout type="warn" title="别在回调里做重活">
回调在关键路径上执行。写数据库、发网络请求要异步且快速，避免拖慢主链路或造成阻塞。
</Callout>

**完整实现**

关键点：回调的每个事件都会带一个 `runId`，用它作为 key 记录开始时间，在对应的 `end` 事件里相减，就能正确处理并发调用。

```ts
// timing-handler.ts
import { BaseCallbackHandler } from "@langchain/core/callbacks/base";

export class TimingHandler extends BaseCallbackHandler {
  name = "TimingHandler";

  // runId → 开始时间戳
  private starts = new Map<string, number>();

  // 汇总数据
  retrieverMs = 0;
  llmMs = 0;
  retrieverCalls = 0;
  llmCalls = 0;
  docsRetrieved = 0;
  promptTokens = 0;
  completionTokens = 0;
  totalTokens = 0;

  // ---------- 检索 ----------
  async handleRetrieverStart(_retriever: any, _query: string, runId: string) {
    this.starts.set(runId, Date.now());
  }

  async handleRetrieverEnd(documents: any[], runId: string) {
    const t0 = this.starts.get(runId);
    if (t0 !== undefined) {
      this.retrieverMs += Date.now() - t0;
      this.starts.delete(runId);
    }
    this.retrieverCalls += 1;
    this.docsRetrieved += documents.length;
  }

  async handleRetrieverError(_err: Error, runId: string) {
    this.starts.delete(runId);
  }

  // ---------- 模型 ----------
  async handleLLMStart(_llm: any, _prompts: string[], runId: string) {
    this.starts.set(runId, Date.now());
  }

  async handleLLMEnd(output: any, runId: string) {
    const t0 = this.starts.get(runId);
    if (t0 !== undefined) {
      this.llmMs += Date.now() - t0;
      this.starts.delete(runId);
    }
    this.llmCalls += 1;

    // Token 用量在不同厂商下字段名不同，做兼容取值
    const usage =
      output.llmOutput?.tokenUsage ??          // OpenAI 常见
      output.llmOutput?.usage ??               // 部分厂商
      output.generations?.[0]?.[0]?.message?.usage_metadata;  // 新版 AIMessage

    if (usage) {
      this.promptTokens += usage.promptTokens ?? usage.input_tokens ?? 0;
      this.completionTokens += usage.completionTokens ?? usage.output_tokens ?? 0;
      this.totalTokens +=
        usage.totalTokens ??
        usage.total_tokens ??
        (usage.promptTokens ?? usage.input_tokens ?? 0) +
          (usage.completionTokens ?? usage.output_tokens ?? 0);
    }
  }

  async handleLLMError(_err: Error, runId: string) {
    this.starts.delete(runId);
  }

  report() {
    console.log("\n===== 本次调用统计 =====");
    console.log(`检索：${this.retrieverCalls} 次，共 ${this.retrieverMs} ms，取回 ${this.docsRetrieved} 块`);
    console.log(`生成：${this.llmCalls} 次，共 ${this.llmMs} ms`);
    console.log(`Token：输入 ${this.promptTokens} + 输出 ${this.completionTokens} = 共 ${this.totalTokens}`);

    const known = this.retrieverMs + this.llmMs;
    console.log(`其中检索占 ${((this.retrieverMs / known) * 100).toFixed(1)}%，生成占 ${((this.llmMs / known) * 100).toFixed(1)}%`);
  }
}
```

**使用**

```ts
import { TimingHandler } from "./timing-handler";

const handler = new TimingHandler();

const t0 = Date.now();
const answer = await ragChain.invoke(
  { question: "如何申请测试环境？" },
  { callbacks: [handler] }        // 局部挂载，只对本次生效
);
const wallMs = Date.now() - t0;

console.log("回答：", answer);
console.log("端到端总耗时：", wallMs, "ms");
handler.report();
```

**典型输出**

```
回答： 在内网工单系统提交「测试环境申请」……
端到端总耗时： 3180 ms

===== 本次调用统计 =====
检索：1 次，共 420 ms，取回 4 块
生成：1 次，共 2680 ms
Token：输入 1245 + 输出 186 = 共 1431
其中检索占 13.5%，生成占 86.5%
```

一眼就能看出瓶颈在生成而非检索——这正是这类回调的价值：**优化前先量一量**，别凭感觉去调。

**几个关键细节**

| 细节 | 说明 |
|---|---|
| 必须用 `runId` 配对 | 若用单个 `this.startTime` 变量，一旦有并行检索（如 `RunnableMap`）或多次 LLM 调用，时间就会互相覆盖，算出负数或离谱值 |
| Token 字段要兼容取值 | OpenAI 在 `llmOutput.tokenUsage`，Anthropic 和新版消息在 `usage_metadata`，写死一个字段换厂商就拿不到 |
| 流式下拿不到 Token | `streaming: true` 时多数厂商不在流末尾返回用量。需要在模型上设 `streamUsage: true`（OpenAI），否则 Token 统计恒为 0 |
| 各段耗时之和 < 端到端 | 差值是提示词拼装、解析、网络等开销。差得太多说明有隐藏瓶颈值得查 |
| 别在回调里做重活 | 课文警告过。这里只做内存累加，若要落库请 `void writeAsync()` 不阻塞主链路 |

**扩展一：按 Token 估算成本**

```ts
const PRICE = { in: 0.15 / 1_000_000, out: 0.6 / 1_000_000 };  // gpt-4o-mini 每 token 美元价
const cost = handler.promptTokens * PRICE.in + handler.completionTokens * PRICE.out;
console.log(`本次成本约 $${cost.toFixed(6)}`);
```

**扩展二：用 `streamEvents` 达到同样效果（无需写类）**

如果只是临时排查，不想定义 handler 类，`streamEvents` 更轻便：

```ts
const timers = new Map<string, number>();

for await (const ev of ragChain.streamEvents({ question: "..." }, { version: "v2" })) {
  if (ev.event.endsWith("_start")) timers.set(ev.run_id, Date.now());
  if (ev.event.endsWith("_end")) {
    const t0 = timers.get(ev.run_id);
    if (t0) console.log(`${ev.name} 耗时 ${Date.now() - t0} ms`);
  }
}
```

**扩展三：交给 LangSmith**

配好 `LANGCHAIN_TRACING_V2=true` 后，上面这些数据会自动以瀑布图呈现，还能跨次对比。自己写 handler 的价值在于**把指标接进你自己的监控系统**（Prometheus、日志平台），两者并不冲突，可以同时开。

## 小结

- Callbacks 是 Langchain 的事件钩子，可监听每一步 start/end/error
- 自定义 `BaseCallbackHandler` 实现日志、计费、监控
- 配置 `LANGCHAIN_*` 环境变量即可零代码接入 LangSmith
