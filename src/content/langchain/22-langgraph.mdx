# LangGraph 入门：状态图与多步 Agent

第 12 章的 `AgentExecutor` 适合线性工具调用。当流程需要「循环、分支、人工审核、长期状态」时，LangGraph 更合适——它把应用建模成一张**状态图（StateGraph）**：节点是步骤，边是流转，状态在节点间累积。

## 1. 定义状态与节点

状态用 `Annotation` 声明，并指定「多个节点如何合并同一字段」：

```ts
import { StateGraph, Annotation, START, END } from "@langchain/langgraph";
import { ChatOpenAI } from "@langchain/openai";

const State = Annotation.Root({
  messages: Annotation<{ role: string; content: string }[]>({
    reducer: (a, b) => a.concat(b),
    default: () => [],
  }),
  step: Annotation<number>({ default: () => 0 }),
});

const model = new ChatOpenAI({ model: "gpt-4o-mini" });

async function agent(state: typeof State.State) {
  const res = await model.invoke(state.messages);
  return {
    messages: [{ role: "assistant", content: res.content as string }],
    step: state.step + 1,
  };
}
```

## 2. 加边与条件路由

`START` 是入口，`END` 是终点；`addConditionalEdges` 让模型决定下一步走向，实现循环或分支：

```ts
function route(state: typeof State.State) {
  if (state.step >= 5) return END;
  if (state.messages.at(-1)?.content.includes("完成")) return END;
  return "agent";
}

const graph = new StateGraph(State)
  .addNode("agent", agent)
  .addEdge(START, "agent")
  .addConditionalEdges("agent", route, { agent: "agent", [END]: END })
  .compile();

const out = await graph.invoke({
  messages: [{ role: "user", content: "逐步规划一次产品发布" }],
});
```

<Callout type="info" title="为什么用 LangGraph">
相比 `AgentExecutor`，它支持：①多节点循环（不止一次工具调用）；②可中断/恢复（human-in-the-loop）；③显式状态管理。复杂 Agent 首选。
</Callout>

## 3. 与工具结合

把第 12 章的工具包装成节点，用条件边在「调用工具」与「结束」间切换，即可重建一个可控的 ReAct 循环。

<Callout type="tip" title="可观测">
LangGraph 与 LangSmith 天然兼容，`compile()` 后的图在 `LANGCHAIN_TRACING_V2=true` 下会被完整追踪每一步状态。
</Callout>

把上面的示例改成「带工具」的图：新增一个 `toolNode`，让 `route` 根据模型是否请求工具决定走 `toolNode` 还是 `END`。

<Answer>
**参考答案：**

给模型 `bind_tools` 后，新增 `tool_node` 节点，并用条件路由在「调用工具」和「结束」之间切换：

```python
from langgraph.graph import StateGraph, START, END, MessagesState
from langchain_openai import ChatOpenAI
from langchain_core.tools import tool
from langchain_core.messages import ToolMessage

model = ChatOpenAI(model="gpt-4o-mini").bind_tools([search_api])


@tool
def search_api(keyword: str) -> str:
    """按关键词搜索知识库，返回匹配的文档内容"""
    return f"关于 {keyword} 的文档：……"


# 1. 工具节点：取出模型的工具调用请求，执行并回填结果
def tool_node(state):
    last = state["messages"][-1]
    args = last.tool_calls[0]["args"]
    return {
        "messages": [
            ToolMessage(
                content=str(search_api.invoke(args)),
                tool_call_id=last.tool_calls[0]["id"],
            )
        ]
    }


# 2. 模型节点：只负责生成，不直接改状态
def agent(state):
    return {"messages": [model.invoke(state["messages"])]}


# 3. 条件路由：模型请求了工具就走 tool_node，否则结束
def route(state):
    last = state["messages"][-1]
    return "tool_node" if last.tool_calls else END


graph = (
    StateGraph(MessagesState)
    .add_node("agent", agent)
    .add_node("tool_node", tool_node)
    .add_edge(START, "agent")
    .add_conditional_edges("agent", route, {"tool_node": "tool_node", END: END})
    .add_edge("tool_node", "agent")  # 工具执行完回到模型，形成 ReAct 循环
    .compile()
)

out = graph.invoke({"messages": [{"role": "user", "content": "搜索「接口返回 500」怎么处理"}]})
```

关键点：

- `bind_tools` 让模型能「请求」调用工具，请求记录在最后一条消息的 `tool_calls` 字段里；
- `route` 判断 `tool_calls` 是否为空：有 → `tool_node`，没有 → `END`，从而既能执行工具也能正常终止；
- 工具结果必须以 `ToolMessage` 回填，且 `tool_call_id` 与模型的请求 ID 一致，模型才能正确消费；
- `tool_node` 连回 `agent`，形成「思考 → 调工具 → 再思考」的循环，直到模型不再请求工具。
</Answer>
</Callout>

## 小结

- LangGraph 用 `StateGraph` 把流程建成状态图，节点累积状态
- `Annotation` 的 `reducer` 决定字段如何合并
- `addConditionalEdges` + `START/END` 实现循环与分支
- 适合需要循环、中断、长期状态的多步 Agent
