# 枚举与模式匹配

**枚举（enum）** 让你定义一个「可能是几种类型之一」的类型。Rust 的枚举极强大：每个变体可携带不同数据。

## 1. 基础枚举

```rust
enum Direction {
    North,
    South,
    East,
    West,
}

fn main() {
    let d = Direction::North;
}
```

## 2. 携带数据的枚举

<Playground

    Quit,                        // 无数据

fn handle(m: &Message) {
    match m {
        Message::Quit => println!("退出"),
        Message::Move { x, y } => println!("移动到 ({}, {})", x, y),
        Message::Write(text) => println!("写入: {}", text),

    }
}

fn main() {
    handle(&Message::Write(String::from("hi")));
    handle(&Message::Move { x: 3, y: 4 });
    handle(&Message::ChangeColor(255, 0, 0));
    handle(&Message::Quit);
}`}

## 3. Option：没有 null 的世界

Rust 没有 `null`。用标准库 `Option<T>` 表达「可能有值」：

```rust
enum Option<T> {
    Some(T),
    None,
}
```

用它彻底消灭空指针异常：

<Playground
  language="rust"
  id="rust-09-option"
  title="Option 与 match"
  code={`fn divide(a: f64, b: f64) -> Option<f64> {
    if b == 0.0 { None } else { Some(a / b) }
}

fn main() {
    match divide(10.0, 2.0) {
        Some(v) => println!("结果 {}", v),
        None => println!("除零错误"),
    }

    match divide(1.0, 0.0) {
        Some(v) => println!("结果 {}", v),
        None => println!("除零错误"),
    }
}`}
  expectedOutput={`结果 5\n除零错误`}
/>

<Callout type="warn" title="Option 强制你处理 None">
因为 `Option<T>` 不是 `T`，你**必须**用 `match`/`if let` 把它拆开才能拿到里面的值。编译器逼你处理「没有值」的情况，从根上避免空引用崩溃。
</Callout>

## 4. if let / while let 简化匹配

只关心一个分支时，不必写完整 `match`：

<Playground
  language="rust"
  id="rust-09-if-let"
  title="if let / while let"
  code={`fn main() {
    let some = Some(7);
    if let Some(n) = some {
        println!("得到 {}", n);
    }

    let mut stack = vec![Some(1), None, Some(2)];
    while let Some(v) = stack.pop() {
        println!("{:?}", v);
    }
}`}
  expectedOutput={`得到 7\nSome(2)\nNone\nSome(1)`}
/>

<Callout type="tip" title="match 还是 if let">
需要穷尽处理所有变体用 `match`；只关心某个变体、其余忽略时用 `if let`，更简洁。
</Callout>

## 6. 实战：计算表达式

```rust
enum Expr {
    Num(i32),
    Add(Box<Expr>, Box<Expr>),
}
```

<Callout type="exercise" title="练习">
定义一个 `enum Shape { Circle(f64), Rectangle(f64, f64) }`，写一个 `fn area(s: &Shape) -> f64` 用 `match` 计算面积（圆用 π·r²）。再补一个 `Triangle` 变体，体会穷尽性要求你同步更新 match。

<Answer>
**参考答案：**

**第一步：两个变体的版本**

```rust
#[derive(Debug)]
enum Shape {
    Circle(f64),           // 半径
    Rectangle(f64, f64),   // 宽、高
}

fn area(s: &Shape) -> f64 {
    match s {
        Shape::Circle(r) => std::f64::consts::PI * r * r,
        Shape::Rectangle(w, h) => w * h,
    }
}

fn main() {
    let shapes = vec![
        Shape::Circle(2.0),
        Shape::Rectangle(3.0, 4.0),
    ];

    for s in &shapes {
        println!("{:?} 面积 = {:.2}", s, area(s));
    }
}
```

**输出：**

```text
Circle(2.0) 面积 = 12.57
Rectangle(3.0, 4.0) 面积 = 12.00
```

**第二步：加上 Triangle，观察穷尽性检查**

只在枚举里加变体、**不改** `match`：

```rust
enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Triangle(f64, f64),    // 底、高
}
```

编译立刻失败：

```text
error[E0004]: non-exhaustive patterns: `&Shape::Triangle(_, _)` not covered
 --> src/main.rs:9:11
  |
9 |     match s {
  |           ^ pattern `&Shape::Triangle(_, _)` not covered
  |
note: `Shape` defined here
  |
2 | enum Shape {
  |      -----
5 |     Triangle(f64, f64),
  |     -------- not covered
  = note: the matched value is of type `&Shape`
help: ensure the match is exhaustive by adding a match arm
```

**这就是穷尽性检查的价值：** 你在一处（枚举定义）新增了一种情况，编译器会把**所有**需要同步更新的 `match` 全部找出来。在大型项目里，这意味着「加了新状态却忘了在某个分支处理」这类 bug 根本无法编译通过。

**第三步：补全后的完整版本**

```rust
use std::f64::consts::PI;

#[derive(Debug)]
enum Shape {
    Circle(f64),
    Rectangle(f64, f64),
    Triangle(f64, f64),
}

impl Shape {
    // 枚举同样可以有方法，这样写更地道
    fn area(&self) -> f64 {
        match self {
            Shape::Circle(r) => PI * r * r,
            Shape::Rectangle(w, h) => w * h,
            Shape::Triangle(base, height) => 0.5 * base * height,
        }
    }

    fn name(&self) -> &str {
        match self {
            Shape::Circle(_) => "圆形",
            Shape::Rectangle(..) => "矩形",
            Shape::Triangle(..) => "三角形",
        }
    }
}

fn main() {
    let shapes = vec![
        Shape::Circle(2.0),
        Shape::Rectangle(3.0, 4.0),
        Shape::Triangle(6.0, 5.0),
    ];

    let mut total = 0.0;
    for s in &shapes {
        println!("{} 面积 = {:.2}", s.name(), s.area());
        total += s.area();
    }
    println!("总面积 = {:.2}", total);
}
```

**输出：**

```text
圆形 面积 = 12.57
矩形 面积 = 12.00
三角形 面积 = 15.00
总面积 = 39.57
```

**几个细节：**

- **`match s` 中 `r` 的类型**：因为 `s` 是 `&Shape`，按理说 `r` 应该是 `&f64`。得益于**匹配人体工程学（match ergonomics）**，Rust 会自动解引用，`r` 直接就是 `f64`，可以参与算术运算而不用写 `*r`
- **`Shape::Rectangle(..)`**：两个点表示「忽略所有字段」，比写 `Shape::Rectangle(_, _)` 更省事
- **不要用 `_ => ` 兜底**：如果 `area` 里写了 `_ => 0.0`，加 `Triangle` 时就**不会报错**了，而是静默返回 0——穷尽性检查的保护作用就此失效。对于自己定义的枚举，宁可把每个变体都列出来
- **`std::f64::consts::PI`** 是标准库提供的圆周率常量，不要自己写 `3.14`
</Answer>
</Callout>

## 小结

- 枚举变体可携带任意数据（单元/元组/结构体风格）
- `Option<T>` 替代 null，强制处理 `None`
- `match` 穷尽匹配；`if let` 简化单分支
- 枚举同样可用 `impl` 加方法
