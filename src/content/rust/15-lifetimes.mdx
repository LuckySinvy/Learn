# 生命周期

**生命周期（lifetime）** 是 Rust 另一项独特机制：它标注引用的「有效范围」，让借用检查器确信返回的引用不会悬垂。

## 1. 为什么需要生命周期

当函数接收多个引用、返回一个引用时，编译器无法判断返回值的引用来自哪个参数：

```rust
// fn longest(x: &str, y: &str) -> &str {   // 编译错误：缺少生命周期标注
//     if x.len() > y.len() { x } else { y }
// }
```

编译器不知道返回的引用该活多久——于是要求你显式标注。

## 2. 生命周期标注 'a

<Playground
  language="rust"
  id="rust-15-longest"
  title="生命周期标注 'a"
  code={`fn longest<'a>(x: &'a str, y: &'a str) -> &'a str {
    if x.len() > y.len() { x } else { y }
}

fn main() {
    let a = String::from("hello world");
    let b = String::from("hi");
    println!("较长的是: {}", longest(&a, &b));
    println!("较长的是: {}", longest("abc", "abcdef"));
}`}
  expectedOutput={`较长的是: hello world\n较长的是: abcdef`}
/>

`'a` 是一个**名字**（任意名称，习惯用 `'a`/`'b`）。含义是：返回的引用，活得不超过 `x` 与 `y` 中**较短**的那个。

<Callout type="info" title="标注不改变生命周期长短">
生命周期标注只是「告诉编译器约束关系」，不会延长或缩短任何数据的存活时间，纯粹是类型检查的信息。
</Callout>

## 3. 结构体中的生命周期

当结构体持有引用，必须标注其生命周期：

<Playground
  language="rust"
  id="rust-15-struct-lifetime"
  title="结构体中的生命周期"
  code={`struct Excerpt<'a> {
    part: &'a str,   // 引用必须活得比结构体久
}

impl<'a> Excerpt<'a> {
    // 规则3：&self 的生命周期赋给输出，无需手写标注
    fn announce(&self, msg: &str) -> &str {
        println!("注意: {}", msg);
        self.part
    }
}

fn main() {
    let s = String::from("hello world");
    let ex = Excerpt { part: &s[0..5] };
    println!("{}", ex.part);
    println!("{}", ex.announce("请阅读摘录"));
}`}
  expectedOutput={`hello\n注意: 请阅读摘录\nhello`}
/>

<Callout type="warn" title="结构体引用不能比数据活得久">
若 `s` 在 `ex` 之前 drop，就悬垂了。编译器用 `'a` 强制「`s` 至少活到 `ex` 用完」。
</Callout>

## 4. 生命周期省略规则

多数函数不用手写标注，编译器按三条规则自动推导：

1. 每个引用参数各有一个独立生命周期。
2. 若**只有**一个输入生命周期，它赋给所有输出。
3. 若有 `&self`/`&mut self`，其生命周期赋给所有输出。

```rust
fn first_word(s: &str) -> &str { ... }   // 规则2：输入唯一，输出同生命周期
```

## 5. 'static 生命周期

`'static` 表示「整个程序运行期都有效」。字符串字面量就是 `&'static str`；`Box::leak` 也能造 `'static`。

<Callout type="tip" title="遇到 'static 报错">
常见错误是把 `&str` 与 `String` 混用或返回局部引用。多数情况下你并不需要真正的 `'static`，标注正确输入生命周期即可。
</Callout>

<Callout type="exercise" title="练习">
实现 `fn longest_with_default<'a>(x: &'a str, y: &'a str, ann: &str) -> &'a str`，先打印 `ann`，再比较长度返回较长者。去掉标注看编译器如何提示你补上。

<Answer>
**参考答案：**

```rust
fn longest_with_default<'a>(x: &'a str, y: &'a str, ann: &str) -> &'a str {
    println!("公告：{}", ann);
    if x.len() > y.len() { x } else { y }
}

fn main() {
    let a = String::from("hello world");
    let b = String::from("hi");

    let result = longest_with_default(&a, &b, "正在比较两个字符串");
    println!("较长的是：{}", result);

    // ann 是字面量还是 String 都无所谓，它的生命周期与返回值无关
    let note = String::from("第二次比较");
    println!("较长的是：{}", longest_with_default("abc", "abcdef", &note));
}
```

**输出：**

```text
公告：正在比较两个字符串
较长的是：hello world
公告：第二次比较
较长的是：abcdef
```

**注意 `ann` 没有标注 `'a`**

这是本题的精髓。`ann` 只是被打印一下，**它的引用不会出现在返回值里**，所以它的生命周期和返回值毫无关系。编译器会按省略规则给它分配一个独立的匿名生命周期。

如果强行给它也标上 `'a`，程序仍能编译，但**约束被不必要地收紧了**——调用方会被要求 `ann` 也得活得和返回值一样久，这在某些场景下会导致本该合法的代码被拒绝。**生命周期标注要尽可能宽松**，只在真正相关的参数间建立联系。

**去掉标注会怎样？**

```rust
fn longest_with_default(x: &str, y: &str, ann: &str) -> &str {
    println!("公告：{}", ann);
    if x.len() > y.len() { x } else { y }
}
```

```text
error[E0106]: missing lifetime specifier
 --> src/main.rs:1:56
  |
1 | fn longest_with_default(x: &str, y: &str, ann: &str) -> &str {
  |                            ----     ----       ----     ^ expected named lifetime parameter
  |
  = help: this function's return type contains a borrowed value, but the
          signature does not say whether it is borrowed from `x`, `y`, or `ann`
help: consider introducing a named lifetime parameter
  |
1 | fn longest_with_default<'a>(x: &'a str, y: &'a str, ann: &'a str) -> &'a str {
  |                        ++++     ++          ++            ++          ++
```

**为什么省略规则在这里失效？** 回顾三条规则：

1. 每个引用参数各得一个独立生命周期 → 这里有三个：`'1`、`'2`、`'3`
2. **只有一个**输入生命周期时，赋给所有输出 → 有三个，不适用
3. 有 `&self` 时，把 self 的生命周期赋给输出 → 这不是方法，不适用

三条规则都用不上，编译器只能求助于你。注意编译器的建议是「三个参数都标 `'a`」——这是最保守的方案，能编译但过度收紧。**你自己写的版本（只标 `x` 和 `y`）更精确。**

**验证生命周期检查真的在工作：**

```rust
fn main() {
    let a = String::from("hello world");
    let result;
    {
        let b = String::from("hi");
        result = longest_with_default(&a, &b, "test");
    }   // b 在这里被 drop
    println!("{}", result);   // ❌ 编译错误
}
```

```text
error[E0597]: `b` does not live long enough
  --> src/main.rs:6:47
   |
5  |         let b = String::from("hi");
   |             - binding `b` declared here
6  |         result = longest_with_default(&a, &b, "test");
   |                                           ^^ borrowed value does not live long enough
7  |     }
   |     - `b` dropped here while still borrowed
8  |     println!("{}", result);
   |                    ------ borrow later used here
```

有意思的是，**即便运行时返回的其实是 `a`**（因为 `"hello world"` 更长），编译器依然拒绝。因为生命周期是**静态分析**——`'a` 被推导为 `a` 和 `b` 中较短的那个，编译器不会去推演运行时的分支走向。这就是「宁可保守也不放过」的取舍。

**换个角度理解 `'a` 的含义：**

`'a` 不是「让 x 和 y 活一样久」，而是**在两者存活期的交集里取一个区间**，返回值只能在这个区间内使用。你可以把它读成一句承诺：

> 「我返回的引用，其数据来自 x 或 y，所以你在用它的时候，必须保证 x 和 y 都还活着。」

**如果返回值其实和输入无关，就不需要标注：**

```rust
fn always_greeting(_x: &str, _y: &str) -> &'static str {
    "你好"   // 字面量是 'static，不借用任何参数
}
```

这里返回的是程序二进制中的静态数据，跟参数没有任何借用关系，所以标 `'static` 即可，不用引入 `'a`。
</Answer>
</Callout>

## 小结

- 生命周期标注 `'a` 描述引用存活约束，不改变实际存活
- 返回引用且有多参数时，需显式标注
- 结构体含引用必须标生命周期
- 省略规则让常见情况免标注；`'static` 贯穿全程
