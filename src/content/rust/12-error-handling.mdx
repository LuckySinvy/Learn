# 错误处理

Rust 没有异常。可恢复错误用 `Result<T, E>` 表示，不可恢复错误用 `panic!`。

## 1. Result 枚举

```rust
enum Result<T, E> {
    Ok(T),
    Err(E),
}
```

文件操作同理，`File::open` 返回的也是 `Result`：

```rust
use std::fs::File;

fn main() {
    let f = File::open("a.txt");
    match f {
        Ok(file) => println!("打开成功"),
        Err(e) => println!("失败: {}", e),
    }
}
```

<Callout type="info" title="错误也是值">
`Result` 把「可能失败」编码进类型。调用者必须处理 `Err`，无法假装它不存在——这比异常更不容易被遗漏。
</Callout>

## 2. panic! 与不可恢复错误

```rust
fn main() {
    // panic!("程序无法继续");
    let v = vec![1, 2, 3];
    println!("{}", v[99]);   // 越界会自动 panic
}
```

`panic` 会展开栈（默认）或终止进程。仅用于「确实是 bug、无法合理恢复」的情况。

## 3. unwrap 与 expect

开发期便捷，但 panic 风险高：

```rust
let f = File::open("a.txt").unwrap();           // Err 时 panic，信息简单
let f = File::open("a.txt").expect("打开失败");  // Err 时 panic，带自定义信息
```

<Callout type="warn" title="unwrap 在库代码中要避免">
`unwrap`/`expect` 一旦遇到 `Err` 就 panic。库代码应把 `Result` 返回给调用者，由上层决定如何处理。仅在示例/测试里图方便时使用。
</Callout>

## 4. ? 运算符传播错误

`?` 是传播错误的语法糖：遇到 `Err` 立即 `return`，否则取出 `Ok` 的值：

```rust
use std::fs::File;
use std::io::{self, Read};

fn read_text() -> Result<String, io::Error> {
    let mut f = File::open("a.txt")?;   // 失败则提前返回 Err
    let mut s = String::new();
    f.read_to_string(&mut s)?;
    Ok(s)
}
```

同样的模式用在解析上，可在沙箱里直接运行：

## 5. 自定义错误类型

用 `Box<dyn std::error::Error>` 兜底，或定义自己的枚举并实现 `std::error::Error`：

```rust
fn run() -> Result<(), Box<dyn std::error::Error>> {
    let _ = read_text()?;
    Ok(())
}
```

<Callout type="tip" title="? 要求错误类型兼容">
`?` 会把当前错误 `From` 转换为函数返回的 `E`。配合 `Box<dyn Error>` 最省事；大型项目常定义统一错误枚举。
</Callout>

## 6. Option 与错误

`Option` 的 `ok_or` 可在需要时转成 `Result`：

```rust
let val = some_option.ok_or("缺少值")?;
```

<Callout type="exercise" title="练习">
写一个 `fn read_first_line(path: &str) -> Result<String, Box<dyn std::error::Error>>`，用 `?` 打开文件并读取第一行返回。在 `main` 里调用，用 `match` 打印成功内容或错误。

<Answer>
**参考答案：**

```rust
use std::error::Error;
use std::fs::File;
use std::io::{BufRead, BufReader};

fn read_first_line(path: &str) -> Result<String, Box<dyn Error>> {
    let file = File::open(path)?;            // io::Error 自动转成 Box<dyn Error>
    let reader = BufReader::new(file);

    // lines() 返回 Iterator<Item = Result<String, io::Error>>
    // next() 返回 Option<Result<String, io::Error>>
    match reader.lines().next() {
        Some(line) => Ok(line?),             // 读行本身也可能失败（如非 UTF-8）
        None => Err("文件为空".into()),      // &str 可以直接 .into() 成 Box<dyn Error>
    }
}

fn main() {
    for path in ["Cargo.toml", "不存在的文件.txt"] {
        match read_first_line(path) {
            Ok(line) => println!("[{}] 第一行：{}", path, line),
            Err(e) => println!("[{}] 出错：{}", path, e),
        }
    }
}
```

**输出：**

```text
[Cargo.toml] 第一行：[package]
[不存在的文件.txt] 出错：No such file or directory (os error 2)
```

**关键点解析：**

- **`?` 做了两件事**：遇到 `Err` 就提前 `return`；同时通过 `From` trait 把错误类型转换成函数签名声明的类型。这里 `io::Error` 被自动装箱成 `Box<dyn Error>`，完全不用手写转换代码
- **为什么用 `Box<dyn Error>`**：函数里可能冒出 `io::Error`、`Utf8Error`、自定义错误等多种类型。`Box<dyn Error>` 是一个 trait 对象，能装下任何实现了 `Error` 的类型，写应用层代码时最省事
- **`"文件为空".into()`**：标准库为 `&str` 实现了 `Into<Box<dyn Error>>`，所以能直接把字符串当错误用。适合快速原型，正式项目建议用具名错误类型
- **为什么用 `BufReader`**：直接用 `File` 逐字节读会有大量系统调用。`BufReader` 加了缓冲，并提供 `lines()` 这类按行读取的便捷方法。**不要用 `read_to_string` 再 `split`**——那会把整个文件读进内存，处理大文件时很浪费
- **`Ok(line?)` 的双层拆包**：`lines()` 的每一项本身就是 `Result`，因为读取过程随时可能出 I/O 错误

**更简洁的写法（用 Option 组合子）：**

```rust
fn read_first_line(path: &str) -> Result<String, Box<dyn Error>> {
    let reader = BufReader::new(File::open(path)?);
    let line = reader.lines().next().ok_or("文件为空")??;
    Ok(line)
}
```

`ok_or` 把 `Option` 转成 `Result`，然后两个 `?` 依次拆开两层——虽然紧凑，但可读性略差。

**进阶：定义自己的错误枚举**

库代码通常不用 `Box<dyn Error>`（它会丢失类型信息，调用方无法针对不同错误做不同处理），而是定义专用枚举：

```rust
use std::fmt;

#[derive(Debug)]
enum ReadError {
    Io(std::io::Error),
    Empty,
}

impl fmt::Display for ReadError {
    fn fmt(&self, f: &mut fmt::Formatter) -> fmt::Result {
        match self {
            ReadError::Io(e) => write!(f, "读取失败：{}", e),
            ReadError::Empty => write!(f, "文件为空"),
        }
    }
}

impl std::error::Error for ReadError {}

// 实现 From，? 就能自动转换
impl From<std::io::Error> for ReadError {
    fn from(e: std::io::Error) -> Self {
        ReadError::Io(e)
    }
}

fn read_first_line(path: &str) -> Result<String, ReadError> {
    let reader = BufReader::new(File::open(path)?);   // 自动走 From
    reader.lines().next().ok_or(ReadError::Empty)?.map_err(ReadError::Io)
}
```

这样调用方可以 `match` 区分「文件打不开」和「文件是空的」，分别采取不同的恢复策略。

**实践建议：** 二进制程序（应用层）用 `Box<dyn Error>` 或 `anyhow` crate；库要用具名错误类型或 `thiserror` crate 来自动生成上面这些样板代码。

**顺带一提：** `main` 函数本身也能返回 `Result`，这样就能在顶层直接用 `?`：

```rust
fn main() -> Result<(), Box<dyn Error>> {
    let line = read_first_line("Cargo.toml")?;
    println!("{}", line);
    Ok(())
}
```

出错时进程会以非零状态码退出，并把错误的 `Debug` 表示打印到 stderr。
</Answer>
</Callout>

## 小结

- `Result<T,E>` 表达可恢复错误；`panic!` 用于不可恢复 bug
- `unwrap`/`expect` 便捷但有 panic 风险，库代码慎用
- `?` 传播错误并自动 `From` 转换，最优雅
- 自定义错误可用 `Box<dyn Error>` 或专用枚举
