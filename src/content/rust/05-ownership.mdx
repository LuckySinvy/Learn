# 所有权

**所有权（Ownership）** 是 Rust 最独特的特性，它让 Rust 无需垃圾回收也能保证内存安全。每个值都有唯一的「所有者」。

## 1. 三条规则

1. 每个值有且仅有一个**所有者**（owner）。
2. 同一时刻只能有一个所有者。
3. 当所有者离开作用域，值被自动释放（`drop`）。

```rust
fn main() {
    {
        let s = String::from("hello");  // s 进入作用域，拥有堆上的字符串
    }                                    // 离开作用域，s 被 drop，内存释放
}
```

<Callout type="info" title="RAII 风格">
Rust 用「资源获取即初始化」思路：值离开作用域就自动清理，无需手动 free，也不会有 GC 停顿。
</Callout>

## 2. 栈与堆

- **栈（stack）**：大小固定、存取极快，存放 `i32`、`char`、以及指向堆的指针。
- **堆（heap）**：大小可变（如 `String`、动态 `Vec`），分配较慢，通过指针访问。

`String` 在栈上存「指针+长度+容量」，真正文本在堆上。正因如此，赋值时会涉及所有权转移。

## 3. move 语义

把值赋给另一个变量（或传参）时，对于堆数据会**转移所有权（move）**，而非深拷贝：

<Playground
  language="rust"
  id="rust-05-move"
  title="move 语义"
  code={`fn main() {
    let s1 = String::from("hello");
    let s2 = s1;          // 所有权从 s1 移到 s2
    // println!("{}", s1); // 编译错误：s1 已失效，避免双重释放
    println!("{}", s2);
}`}
  expectedOutput={`hello`}
/>

<Callout type="warn" title="浅拷贝 + 失效旧绑定">
`let s2 = s1` 只复制了栈上的指针，但 Rust 让 s1 失效，保证不会有两个变量同时释放同一块堆内存。这就是「move」的本质。
</Callout>

## 4. 克隆与拷贝

需要真正复制堆数据时，显式 `clone()`：

```rust
let s1 = String::from("hi");
let s2 = s1.clone();    // 深拷贝，s1 仍可用
```

而 `i32` 等「实现了 `Copy`  trait」的简单类型，赋值会**按位复制**且旧值仍可用：

```rust
let a = 5;
let b = a;              // i32 是 Copy，a 仍可用
```

## 5. 函数传参与返回

传参也是 move，返回值可把所有权「交还」回来：

```rust
fn take(s: String) { /* s 在此 drop */ }
fn give() -> String { String::from("owned") }

fn main() {
    let s = give();     // 获得所有权
    take(s);            // 移交所有权，此后 s 不可用
}
```

<Callout type="exercise" title="练习">
预测并验证：写一个函数 `fn len(s: String) -> usize` 返回字符串长度（内部 `s.len()`），调用后试着再打印原变量，看编译器如何阻止你使用已 move 的值。

<Answer>
**参考答案：**

**会失败的版本：**

```rust
fn len(s: String) -> usize {
    s.len()
}   // s 在这里离开作用域，被 drop（堆内存释放）

fn main() {
    let text = String::from("hello");
    let n = len(text);            // text 的所有权移交给参数 s
    println!("长度 = {}", n);
    println!("原字符串 = {}", text);  // ❌ 编译错误
}
```

**编译器的报错：**

```text
error[E0382]: borrow of moved value: `text`
 --> src/main.rs:9:34
  |
7 |     let text = String::from("hello");
  |         ---- move occurs because `text` has type `String`,
  |              which does not implement the `Copy` trait
8 |     let n = len(text);
  |                 ---- value moved here
9 |     println!("原字符串 = {}", text);
  |                              ^^^^ value borrowed here after move
  |
help: consider cloning the value if the performance cost is acceptable
  |
8 |     let n = len(text.clone());
  |                     ++++++++
```

**报错读懂了什么：**

- 编译器精确指出了三个位置：**在哪里创建**、**在哪里被 move**、**在哪里非法使用**
- 它解释了根因：`String` 没有实现 `Copy`，所以传参是移动而不是复制
- 还附带了修复建议

**三种修复方式：**

**方案一：改成借用（最推荐）**

```rust
fn len(s: &String) -> usize {
    s.len()
}

fn main() {
    let text = String::from("hello");
    let n = len(&text);                  // 只借用，不转移所有权
    println!("长度 = {}", n);
    println!("原字符串 = {}", text);     // ✅ 正常工作
}
```

更地道的签名是用 `&str`，这样字面量和 `String` 都能传：

```rust
fn len(s: &str) -> usize {
    s.len()
}
// len(&text) 和 len("hi") 都可以
```

**方案二：克隆（有堆拷贝开销，非必要不用）**

```rust
let n = len(text.clone());
```

**方案三：把所有权还回来**

```rust
fn len(s: String) -> (String, usize) {
    let n = s.len();
    (s, n)                 // 连同所有权一起返回
}

fn main() {
    let text = String::from("hello");
    let (text, n) = len(text);   // 接回所有权（用 shadowing 重新绑定）
    println!("{} 的长度是 {}", text, n);
}
```

这种写法在 Rust 早期很常见，但很笨拙——**借用机制就是为了取代它而存在的**，这也正是下一章的主题。

**对比实验：** 把 `String` 换成 `i32` 试试，就不会报错了，因为 `i32` 实现了 `Copy`，传参是按位复制，原变量依然有效。
</Answer>
</Callout>

## 小结

- 值有唯一所有者；离开作用域自动 drop
- 堆数据赋值是 move（旧绑定失效），避免双重释放
- `clone()` 深拷贝；`Copy` 类型（如 i32）赋值是位拷贝
- 函数传参移交所有权，返回值可交还
