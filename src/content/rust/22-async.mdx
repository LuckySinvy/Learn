# 异步编程

**异步（async）** 让你用接近同步的写法写出高并发的 I/O 程序——单线程即可处理成千上万并发连接，不靠为每个连接开一个线程。

## 1. Future 与 async

`async fn` 返回一个「将来会完成」的 `Future`，本身**不会立刻执行**，需要运行时去 poll（轮询）它：

```rust
async fn fetch(n: u32) -> u32 {
    // 模拟异步等待
    n * 2
}
```

## 2. await 挂起

`.await` 让当前异步任务「让出」控制权，等结果就绪再继续：

```rust
async fn main_task() {
    let r = fetch(21).await;   // 在此挂起，不阻塞线程
    println!("结果 {}", r);
}
```

<Callout type="info" title="异步不阻塞线程">
遇到 `.await`，任务让出线程去干别的事；等未来就绪，运行时再把它唤醒。一个线程能借此交错运行大量任务。
</Callout>

## 3. 需要运行时：tokio

Rust 标准库只定义 `Future`，不含调度器。社区主流是 **tokio**：

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

```rust
use tokio::time::{sleep, Duration};

#[tokio::main]
async fn main() {
    let h1 = tokio::spawn(async {
        sleep(Duration::from_millis(10)).await;
        "任务1完成"
    });
    let msg = h1.await.unwrap();
    println!("{}", msg);
}
```

<Callout type="tip" title="#[tokio::main] 做了什么">
它是个宏，把你写的 `async fn main` 包进运行时启动代码：创建多线程调度器，再 `block_on(main_task)`。没有它，`Future` 不会被执行。
</Callout>

## 4. 并发运行多个任务

```rust
let (a, b) = tokio::join!(task_a(), task_b());   // 并发等待两者
```

<Callout type="warn" title="别在异步里用阻塞调用">
在 `.await` 之间调用 `std::thread::sleep` 或同步 `read` 会卡住整个线程，拖累所有任务。异步代码要用 tokio 提供的非阻塞版本（`tokio::fs`、`tokio::time::sleep`）。
</Callout>

## 5. async 与线程的关系

- 异步任务运行在「执行器（executor）」管理的线程池上。
- `spawn` 把任务交给调度器；`spawn_blocking` 才适合 CPU 重活。
- 异步擅长 I/O 密集，多线程擅长 CPU 密集。

<Callout type="exercise" title="练习">
用 tokio 起两个 `async` 任务，分别 `sleep` 不同毫秒数后返回字符串，用 `tokio::join!` 并发等待并打印。观察总耗时接近较慢者而非两者之和。

<Answer>
**参考答案：**

先在 `Cargo.toml` 加依赖：

```toml
[dependencies]
tokio = { version = "1", features = ["full"] }
```

`src/main.rs`：

```rust
use std::time::Instant;
use tokio::time::{sleep, Duration};

async fn task_a() -> String {
    sleep(Duration::from_millis(300)).await;
    String::from("任务 A 完成（300ms）")
}

async fn task_b() -> String {
    sleep(Duration::from_millis(500)).await;
    String::from("任务 B 完成（500ms）")
}

#[tokio::main]
async fn main() {
    // ===== 并发执行 =====
    let start = Instant::now();
    let (a, b) = tokio::join!(task_a(), task_b());
    println!("{}", a);
    println!("{}", b);
    println!("并发耗时：{:?}\n", start.elapsed());

    // ===== 对比：串行执行 =====
    let start = Instant::now();
    let a = task_a().await;
    let b = task_b().await;
    println!("{}", a);
    println!("{}", b);
    println!("串行耗时：{:?}", start.elapsed());
}
```

**输出：**

```text
任务 A 完成（300ms）
任务 B 完成（500ms）
并发耗时：500.8ms

任务 A 完成（300ms）
任务 B 完成（500ms）
串行耗时：801.2ms
```

**并发 ≈ 500ms（较慢者），串行 ≈ 800ms（两者之和）。**

**为什么会有这个差异？**

关键在于 **`Future` 是惰性的**——`task_a()` 只是创建了一个 Future，不会立刻开始执行。

- **`join!`**：把两个 Future 交给同一个任务，交替 poll 它们。A 的 `.await` 挂起时，执行器立刻转去推进 B，两者的等待时间**重叠**了
- **连续 `.await`**：第一个 `.await` 完全结束后才创建并推进第二个 Future，等待时间**串行叠加**

**常见误区：`join!` 不等于多线程**

`join!` 里的任务默认跑在**同一个线程**上。它省下的是「等待 I/O 的时间」，而不是「计算的时间」。把 sleep 换成 CPU 密集的循环，`join!` 不会带来任何加速：

```rust
async fn cpu_heavy() -> u64 {
    (0..1_000_000_000u64).sum()   // 纯计算，没有 .await 让出点
}

// join! 这种任务不会变快，反而会阻塞整个执行器线程
```

CPU 密集的活儿要用 `spawn_blocking` 挪到专门的阻塞线程池：

```rust
let result = tokio::task::spawn_blocking(|| {
    (0..1_000_000_000u64).sum::<u64>()
}).await.unwrap();
```

**`tokio::spawn`：真正的并行任务**

`join!` 在当前任务内并发；`spawn` 则把任务交给调度器，可能被分配到线程池的**其他线程**上：

```rust
#[tokio::main]
async fn main() {
    let start = Instant::now();

    let h1 = tokio::spawn(task_a());
    let h2 = tokio::spawn(task_b());

    // spawn 返回 JoinHandle，await 它得到 Result
    let a = h1.await.unwrap();
    let b = h2.await.unwrap();

    println!("{}\n{}", a, b);
    println!("耗时：{:?}", start.elapsed());   // 同样约 500ms
}
```

**`join!` 与 `spawn` 怎么选？**

| | `tokio::join!` | `tokio::spawn` |
|---|---|---|
| 任务数量 | 编译期固定 | 任意，可动态创建 |
| 执行线程 | 当前任务所在线程 | 可能被调度到其他线程 |
| 生命周期 | 可借用外部变量 | 要求 `'static`，通常得 `move` |
| 取消行为 | 整体一起取消 | 独立，句柄丢弃后仍继续跑 |
| 开销 | 极小 | 有任务注册开销 |

**处理动态数量的任务：`join_all`**

任务数量在运行时才确定时，用 `futures` crate：

```rust
use futures::future::join_all;

#[tokio::main]
async fn main() {
    let tasks: Vec<_> = (1..=5)
        .map(|i| async move {
            sleep(Duration::from_millis(i * 100)).await;
            format!("任务 {} 完成", i)
        })
        .collect();

    for r in join_all(tasks).await {
        println!("{}", r);
    }
    // 总耗时约 500ms，而非 1500ms
}
```

**`try_join!`：任一失败就提前返回**

任务返回 `Result` 时，`try_join!` 会在第一个 `Err` 出现时立刻放弃其余任务：

```rust
async fn may_fail(ok: bool) -> Result<String, String> {
    sleep(Duration::from_millis(100)).await;
    if ok { Ok("成功".into()) } else { Err("失败".into()) }
}

#[tokio::main]
async fn main() {
    match tokio::try_join!(may_fail(true), may_fail(false)) {
        Ok((a, b)) => println!("都成功：{} {}", a, b),
        Err(e) => println!("有失败：{}", e),
    }
}
```

**最重要的一条纪律：绝不在 async 里做阻塞调用**

```rust
// ❌ 灾难性写法：卡死整个执行器线程，该线程上所有任务都停摆
async fn bad() {
    std::thread::sleep(Duration::from_secs(1));   // 阻塞！
    let content = std::fs::read_to_string("f.txt").unwrap();   // 阻塞！
}

// ✅ 正确：用异步版本
async fn good() {
    tokio::time::sleep(Duration::from_secs(1)).await;
    let content = tokio::fs::read_to_string("f.txt").await.unwrap();
}
```

异步执行器的线程数通常等于 CPU 核数。一个线程被阻塞，就意味着调度到它上面的**所有**任务都被连累——这是异步编程中后果最严重、也最常见的错误。
</Answer>
</Callout>

## 小结

- `async fn` 返回 `Future`，需运行时 poll 才执行
- `.await` 挂起让出线程，不阻塞
- tokio 提供运行时；`#[tokio::main]` 启动调度器
- 异步适合 I/O 密集，避免在里面做阻塞调用
