# Trait

**trait** 定义一种「类型能做什么」的抽象接口，类似其他语言的接口（interface）。它是 Rust 实现多态与代码复用核心。

## 1. 定义与实现 trait

<Playground
  language="rust"
  id="rust-14-trait"
  title="定义与实现 trait"
  code={`trait Summary {
    fn summarize(&self) -> String;
}

struct News {
    headline: String,
}

impl Summary for News {
    fn summarize(&self) -> String {
        format!("头条: {}", self.headline)
    }
}

fn main() {
    let n = News { headline: String::from("Rust 1.0 发布") };
    println!("{}", n.summarize());
}`}
  expectedOutput={`头条: Rust 1.0 发布`}
/>

<Callout type="info" title="trait 是能力契约">
trait 只声明「有哪些方法」。一个类型 `impl` 了某 trait，就意味着它具备该能力，可被要求该能力的泛型/trait bound 接受。
</Callout>

## 2. 默认方法实现

```rust
trait Summary {
    fn author(&self) -> String;
    fn summarize(&self) -> String {
        format!("(作者: {})", self.author())   // 默认实现可调用其他方法
    }
}

impl Summary for News {
    fn author(&self) -> String { String::from("编辑部") }
}
```

## 3. trait 作为约束（trait bound）

```rust
fn notify<T: Summary>(item: &T) {
    println!("通知: {}", item.summarize());
}
```

也可用 `impl Trait` 简写：`fn notify(item: &impl Summary)`。

<Callout type="tip" title="impl Trait vs 泛型 bound">
`fn f(x: &impl Trait)` 与 `fn f<T: Trait>(x: &T)` 等价，前者更简洁，仅用于单约束单参数时。
</Callout>

## 4. trait 对象实现运行时多态

用 `&dyn Trait` 存放「任何实现了该 trait 的类型」，在运行时动态分发：

<Playground
  language="rust"
  id="rust-14-dyn"
  title="trait 对象与多态"
  code={`trait Summary {
    fn summarize(&self) -> String;
}

struct News { headline: String }
struct Tweet { user: String }

impl Summary for News {
    fn summarize(&self) -> String {
        format!("头条: {}", self.headline)
    }
}

impl Summary for Tweet {
    fn summarize(&self) -> String {
        format!("@{} 发推", self.user)
    }
}

fn main() {
    let news = News { headline: String::from("Rust 很快") };
    let tweet = Tweet { user: String::from("alice") };

    let items: Vec<&dyn Summary> = vec![&news, &tweet];
    for i in items {
        println!("{}", i.summarize());
    }
}`}
  expectedOutput={`头条: Rust 很快\n@alice 发推`}
/>

<Callout type="warn" title="dyn 有运行时开销">
`dyn Trait` 通过虚表（vtable）动态调用，有轻微开销且大小不固定（需指针）。若编译期多态够用，优先用泛型 + trait bound（静态分发，零开销）。
</Callout>

## 5. 派生 trait

用 `#[derive(...)]` 让编译器自动实现常用 trait：

```rust
#[derive(Debug, Clone, PartialEq)]
struct Point { x: i32, y: i32 }
```

## 6. 返回 impl Trait

```rust
fn make_counter() -> impl FnMut() -> i32 {
    let mut n = 0;
    move || { n += 1; n }
}
```

<Callout type="exercise" title="练习">
定义一个 `trait Draw { fn draw(&self); }`，为 `Circle` 和 `Square` 实现它。写一个函数 `fn render(shapes: &[&dyn Draw])` 遍历绘制。再给 trait 加一个默认方法 `fn name(&self) -> &str { "unknown" }`。

<Answer>
**参考答案：**

```rust
trait Draw {
    // 必须实现的方法
    fn draw(&self);

    // 默认方法：不实现就用这个
    fn name(&self) -> &str {
        "unknown"
    }

    // 默认方法可以调用其他方法（包括必须实现的）
    fn render_with_label(&self) {
        println!("--- {} ---", self.name());
        self.draw();
    }
}

struct Circle {
    radius: f64,
}

struct Square {
    side: f64,
}

struct Triangle {
    base: f64,
    height: f64,
}

impl Draw for Circle {
    fn draw(&self) {
        println!("画一个半径 {} 的圆", self.radius);
    }

    fn name(&self) -> &str {
        "圆形"   // 覆盖默认实现
    }
}

impl Draw for Square {
    fn draw(&self) {
        println!("画一个边长 {} 的正方形", self.side);
    }

    fn name(&self) -> &str {
        "正方形"
    }
}

impl Draw for Triangle {
    fn draw(&self) {
        println!("画一个 {}x{} 的三角形", self.base, self.height);
    }
    // 不实现 name()，会用到默认的 "unknown"
}

// 接收 trait 对象切片：运行时多态
fn render(shapes: &[&dyn Draw]) {
    for s in shapes {
        s.render_with_label();
    }
}

fn main() {
    let c = Circle { radius: 2.0 };
    let s = Square { side: 3.0 };
    let t = Triangle { base: 4.0, height: 5.0 };

    let shapes: Vec<&dyn Draw> = vec![&c, &s, &t];
    render(&shapes);
}
```

**输出：**

```text
--- 圆形 ---
画一个半径 2 的圆
--- 正方形 ---
画一个边长 3 的正方形
--- unknown ---
画一个 4x5 的三角形
```

`Triangle` 没有实现 `name()`，所以自动使用了 trait 里的默认实现。这就是默认方法的价值：**给 trait 添加新方法时，已有的实现者不会被破坏**。

**关键点解析：**

- **`&[&dyn Draw]` 的含义**：一个切片，每个元素是指向「某个实现了 `Draw` 的类型」的引用。具体是 `Circle` 还是 `Square`，编译期不知道，运行时通过 **vtable（虚函数表）** 查找该调哪个 `draw`
- **默认方法可以调用抽象方法**：`render_with_label` 里调用了 `self.name()` 和 `self.draw()`，实际执行的是各类型自己的版本。这就是**模板方法模式**——在 trait 里固化流程骨架，把可变部分交给实现者
- **为什么 `Vec` 需要显式标注 `Vec<&dyn Draw>`**：不标注的话，编译器会从第一个元素推断成 `Vec<&Circle>`，后面塞 `&Square` 就类型不匹配了。标注后会自动把 `&Circle` **强转（unsize coercion）** 成 `&dyn Draw`

**如果需要拥有所有权：用 `Box<dyn Draw>`**

上面的 `&dyn Draw` 要求原对象在别处存活。想让容器自己持有对象，就用 `Box`：

```rust
fn render_owned(shapes: &[Box<dyn Draw>]) {
    for s in shapes {
        s.render_with_label();
    }
}

fn main() {
    let shapes: Vec<Box<dyn Draw>> = vec![
        Box::new(Circle { radius: 2.0 }),
        Box::new(Square { side: 3.0 }),
        Box::new(Triangle { base: 4.0, height: 5.0 }),
    ];
    render_owned(&shapes);
}
```

这是构建「异构集合」最常见的方式——GUI 组件树、插件系统都是这个模式。

**静态分发 vs 动态分发**

如果每次调用的类型在编译期就确定，用泛型更高效：

```rust
// 静态分发：编译期单态化，可内联，零开销
fn render_one<T: Draw>(shape: &T) {
    shape.render_with_label();
}

// 等价的简写
fn render_one2(shape: &impl Draw) {
    shape.render_with_label();
}
```

**如何选择：**

| 场景 | 选择 |
|---|---|
| 集合里要放**多种**不同类型 | `dyn Trait`（动态分发） |
| 每处调用类型**单一**确定 | 泛型 bound（静态分发） |
| 追求极致性能、允许二进制变大 | 泛型 |
| 需要在运行时决定类型、控制代码体积 | `dyn Trait` |

**对象安全的注意事项：** 不是所有 trait 都能做成 `dyn Trait`。如果 trait 里有泛型方法、返回 `Self`、或有不带 `self` 的关联函数，它就**不是对象安全的**，无法用作 trait 对象。比如 `Clone` 就不能写成 `Box<dyn Clone>`，因为 `clone()` 返回 `Self`，编译器无法确定返回值的大小。
</Answer>
</Callout>

## 小结

- trait 抽象「能力」，类型用 `impl` 实现
- 默认方法可复用；trait bound 约束泛型参数
- `impl Trait` 简写单约束；`&dyn Trait` 实现运行时多态
- 派生 trait 一键获得 `Debug`/`Clone` 等
