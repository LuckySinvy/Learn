# 重排序（Re-ranking）

检索（retrieval）追求**快而广**，召回一堆可能相关的候选；重排序（rerank）追求**准而精**，从中挑出真正和问题最匹配的少数几段。两步结合，是高质量 RAG 的关键。

## 1. 为什么需要重排序

向量检索（Bi-Encoder）把问题 and 文档各自编码，**没有让两者真正「互相看」**，容易召回「语义接近但答非所问」的片段。重排序器（Cross-Encoder）则把「问题 + 文档」拼在一起联合打分，精度高得多。

```text
召回 Top-20 (快, 可能含噪声)
        │  rerank
        ▼
精排 Top-5  (准, 真正相关)
```

<Callout type="info" title="两段式是性价比最高的做法">
先用便宜的向量检索广撒网（召回 20–50），再用稍贵的 Cross-Encoder 精排取 5。比「直接向量检索取 5」效果更好，又比「直接精排全库」便宜得多。
</Callout>

## 2. 用 Cross-Encoder 重排

```python
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("BAAI/bge-reranker-large")

pairs = [(question, chunk["text"]) for chunk in candidates]
scores = reranker.predict(pairs)     # 每个 (问题, 文档) 的相关性分

ranked = sorted(zip(candidates, scores), key=lambda x: x[1], reverse=True)
top5 = [c for c, s in ranked[:5]]
```

## 3. 常见重排模型

| 模型 | 提供方 | 特点 |
|---|---|---|
| `bge-reranker-large/base` | BAAI | 中文强、开源、可本地 |
| `gte-reranker` | 阿里 | 中文友好 |
| `cohere-rerank` | Cohere | API 托管、效果稳定、需联网 |
| `jina-reranker` | Jina | 多语言、API |

<Callout type="warn" title="重排是同步瓶颈">
Cross-Encoder 对每对 (问题, 候选) 都要一次前向，候选越多越慢。因此先靠向量检索把候选压到 20–50 再重排，避免对全库精排拖垮延迟。
</Callout>

## 4. 分数融合策略

如果同时有向量分、BM25 分、重排分，可加权融合：

```python
final_score = (
    0.2 * normalize(dense_score)
    + 0.2 * normalize(bm25_score)
    + 0.6 * normalize(rerank_score)
)
```

经验：重排分权重最高，因为它最准。

## 5. 一个完整的两段式流程

```python
candidates = vector_store.search(q_vec, top_k=30)   # 广召回
pairs = [(question, c["text"]) for c in candidates]
scores = reranker.predict(pairs)
top = [candidates[i] for i in argsort(scores)[-5:][::-1]]
```

<Callout type="tip" title="重排后一定要回带原文">
重排只是给候选排序，最终喂给 LLM 的还是 `text` 原文 + `metadata`。排序只是决定「哪几段进上下文、以及先后」。
</Callout>

<Callout type="exercise" title="练习">
取一个你常被「答非所问」召回困扰的问题，先向量检索 Top-20，再重排取 Top-5，对比前后两次进 LLM 的片段，看重排是否剔掉了无关的。

<Answer>
**参考答案：**

**对比脚本**

```python
import numpy as np
from sentence_transformers import CrossEncoder

reranker = CrossEncoder("BAAI/bge-reranker-large")
question = "试用期员工可以休年假吗？"

# 1) 向量广召回 Top-20
cands = vector_store.search(embed(question), top_k=20)

# 2) 记录「重排前的 Top-5」作为基线
before = cands[:5]

# 3) Cross-Encoder 精排
pairs = [(question, c["text"]) for c in cands]
scores = reranker.predict(pairs)
order = np.argsort(scores)[::-1]
after = [cands[i] for i in order[:5]]

# 4) 并排打印对比
print(f"{'重排前 Top-5':<46}| 重排后 Top-5")
print("-" * 96)
for b, a in zip(before, after):
    print(f"{b['text'][:42]:<46}| {a['text'][:42]}")

# 5) 量化变化
before_ids = {c["id"] for c in before}
after_ids  = {c["id"] for c in after}
print(f"\n重排换掉了 {len(after_ids - before_ids)} / 5 个片段")
print(f"新进入的片段原本排在: "
      f"{[cands.index(c) + 1 for c in after if c['id'] not in before_ids]}")
```

**典型输出**

```text
重排前 Top-5                                  | 重排后 Top-5
------------------------------------------------------------------------------------------------
年假天数：满一年 5 天，满十年 10 天           | 试用期内不计入年假累计工龄，转正后方可申请
年假申请需提前 3 个工作日提交 OA              | 年假天数：满一年 5 天，满十年 10 天
试用期考核标准与转正流程说明                  | 试用期考核标准与转正流程说明
病假需提供二级以上医院证明                    | 员工入职满 12 个月起享有带薪年休假
调休规则：加班可折算调休，有效期 3 个月        | 年假申请需提前 3 个工作日提交 OA

重排换掉了 2 / 5 个片段
新进入的片段原本排在: [11, 7]
```

**观察与解读**

1. **真正的答案原本排在第 11 位**。向量检索把它排到了 20 名开外的边缘，如果当初直接 `top_k=5`，这条关键证据**根本不会进入 Prompt**，LLM 只能基于「年假天数」瞎推，大概率答错。这是「广召回 + 精排」价值最直观的体现。

2. **被剔掉的是「主题相关但答非所问」的片段**。「病假需提供医院证明」和「调休规则」在向量空间里离问题很近——都是「假期制度」这个大主题——但它们完全回答不了「试用期能不能休年假」。Bi-Encoder 只能看到主题相似，Cross-Encoder 则真正读懂了问句的**意图**。

3. **为什么 Cross-Encoder 能做到？** 关键在于「问题」和「文档」是否有机会**互相注意**：

```text
Bi-Encoder（向量检索）:
   问题 → [编码器] → 向量A ┐
                          ├→ 算余弦
   文档 → [编码器] → 向量B ┘
   两者各编各的，文档被压成一个向量时，还不知道会被什么问题查询

Cross-Encoder（重排）:
   [问题 + 文档] 拼一起 → [编码器] → 相关性分数
   每个文档 token 都能注意到每个问题 token，能捕捉「试用期」与「不计入工龄」的对应关系
```

代价是**无法预计算**：Bi-Encoder 的文档向量可以离线算好存库里，Cross-Encoder 必须在线对每个（问题,文档）对跑一次前向。20 个候选就是 20 次推理，这就是为什么它只能用于精排、不能用于全库检索。

**几个实践要点**

- **召回数选 20–50 之间**。太少（如 10）则重排没有腾挪空间，捞不回排名靠后的正确答案；太多（如 200）延迟就撑不住了。可以先跑一次统计：正确答案通常出现在向量检索的第几名？如果 95% 的情况都在前 30，那 `top_k=30` 就够了。
- **重排分可以当阈值用**。`bge-reranker` 的输出分数有较稳定的物理意义，若 Top-1 的分数都低于某个阈值（需在自己语料上标定），说明知识库里压根没有相关内容，此时应当**直接回复「未找到相关资料」而不是硬答**，这是抑制幻觉最有效的手段之一。
- **重排会改变片段顺序，而顺序是有影响的**。呼应第 22 章的「Lost in the Middle」：最相关的片段应该放在上下文的开头或结尾，而不是中间。重排后直接按分数降序拼接是合理的默认做法。
- **别忘了带回原文和 metadata**。重排只负责排序，最终喂给 LLM 的仍是 `text` 与来源信息，引用溯源依赖它们。
</Answer>
</Callout>

## 小结

- 检索广而快，重排准而精，两段结合性价比最高
- Cross-Encoder 联合打分，比 Bi-Encoder 精度高
- 先向量召回 20–50，再重排取 5，避免全库精排
- 多路分数可加权融合，重排分权重最高
