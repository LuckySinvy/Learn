# 上下文拼接与 Prompt 组装

检索到的片段最终要被「组装」成一段给 LLM 的 Prompt。组装得好，模型才知道怎么用这些证据；组装得差，再准的检索也白搭。

## 1. 基本模板结构

一个稳健的 RAG Prompt 通常含四部分：系统指令、上下文、问题、输出格式。

```text
你是一个严谨的助手。只能依据下方【资料】回答，
若资料中没有相关信息，回答"我不知道"。

【资料】
1. {chunk_1}
2. {chunk_2}
...

【问题】
{question}

【回答】
```

## 2. 代码化组装

```python
def build_prompt(question, chunks):
    ctx = "\n".join(
        f"[{i+1}] {c['text']}（来源：{c['metadata']['source']} 第{c['metadata']['page']}页）"
        for i, c in enumerate(chunks)
    )
    return f"""你是严谨的助手，仅依据资料作答。
【资料】
{ctx}

【问题】{question}
【回答】"""
```

<Callout type="info" title="给每段编号，方便引用">
为每段上下文加 `[1][2]` 编号，并在指令里要求模型回答时标注 `[1]`，能直接实现「可溯源」（呼应下一章 Citation）。
</Callout>

## 3. token 预算控制

LLM 有上下文窗口上限，检索片段可能超预算：

```python
MAX_TOKENS = 3000
est = lambda s: len(s) / 1.6   # 中文粗略 1 字≈1.6 token 估算

budget, kept = MAX_TOKENS, []
for c in ranked_chunks:        # 已按相关度排序
    if est(c["text"]) > budget:
        if not kept:           # 哪怕超也要留一段
            kept.append(c)
        break
    kept.append(c); budget -= est(c["text"])
```

<Callout type="warn" title="预算超了别硬塞">
把超出窗口的片段硬拼进去会被截断，反而丢掉了最关键的后段。应「按相关度从高到低截取」，并在超预算时提示模型「资料可能不完整」。
</Callout>

## 4. 上下文压缩

当片段冗长但只需其中一句时，可先做压缩：

- **句子级筛选**：只保留与问题 token 重叠高的句子
- **LLM 摘要**：用一个小模型把长 chunk 压成关键句（适合超大文档）
- **去重合并**：MMR 已去冗余，这里避免重复来源

```python
# 简单句子筛选
import re
def keep_relevant(text, question, top_n=3):
    sents = re.split(r"[。！？]", text)
    scored = [(s, overlap(s, question)) for s in sents if s.strip()]
    return "。".join(s for s, _ in sorted(scored, key=lambda x: x[1], reverse=True)[:top_n])
```

## 5. 指令设计要点

| 要点 | 说明 |
|---|---|
| 限定依据 | 「仅依据资料，不得编造」降低幻觉 |
| 未知处理 | 「资料无则答不知道」避免瞎猜 |
| 引用要求 | 「标注 [n] 来源」便于溯源 |
| 语言风格 | 指定输出语言、长度、格式 |

<Callout type="tip" title="把模板当配置管理">
Prompt 模板会随效果调优频繁改。把它抽成独立配置（YAML/DB），和代码分离，方便 A/B 与版本管理，不要硬编码在逻辑里。
</Callout>

**参考答案：**

**改进后的预算控制函数**

课文里的版本有个隐患：遇到一个超长片段就 `break`，会把后面所有较短但同样相关的片段全部丢弃。更稳妥的做法是**跳过放不下的、继续尝试后面的**：

```python
MAX_TOKENS = 3000

def est_tokens(s: str) -> int:
    """中文粗略估算：1 汉字 ≈ 1.6 token，英文按 4 字符 ≈ 1 token"""
    cn = sum(1 for ch in s if '\u4e00' <= ch <= '\u9fff')
    other = len(s) - cn
    return int(cn * 1.6 + other / 4)

def fit_budget(ranked_chunks, max_tokens=MAX_TOKENS, reserve=200):
    """
    ranked_chunks: 已按相关度降序排列
    reserve: 给指令模板、问题本身预留的 token
    """
    budget = max_tokens - reserve
    kept, dropped = [], []

    for c in ranked_chunks:
        need = est_tokens(c["text"]) + 20      # +20 给编号、来源标注
        if need <= budget:
            kept.append(c)
            budget -= need
        else:
            dropped.append(c)                  # 放不下就跳过，继续试下一个

    # 兜底：一段都没留住（首段就超预算）时，截断最相关的那段
    if not kept and ranked_chunks:
        head = dict(ranked_chunks[0])
        limit = int((max_tokens - reserve) / 1.6)
        head["text"] = head["text"][:limit] + "…（片段已截断）"
        kept, dropped = [head], ranked_chunks[1:]

    return kept, dropped
```

chunks = [

**在 Prompt 里告知截断情况**

丢弃了片段却不告诉模型，模型会以为自己看到了全部资料，从而对不完整的信息给出过度自信的断言。正确做法是显式提示：

```python
def build_prompt(question, kept, dropped):
    ctx = "\n\n".join(
        f"[{i+1}] {c['text']}（来源：{c['meta']['source']}）"
        for i, c in enumerate(kept)
    )
    note = ""
    if dropped:
        note = (f"\n注意：因篇幅限制，还有 {len(dropped)} 段相关资料未能展示。"
                f"若下列资料不足以完整回答，请说明「资料可能不完整」，不要臆测。")
    return f"""你是严谨的助手，仅依据资料作答，未知则说不知道，句末标 [n]。{note}
【资料】
{ctx}

【问题】{question}
【回答】"""
```

**四个要点**

1. **`est_tokens` 只是估算，生产要用真 tokenizer**。粗估会有 10–20% 误差，所以上面留了 200 token 的 `reserve` 作为安全垫。精确做法是用 `tiktoken`（OpenAI）或模型自带的 tokenizer：

```python
import tiktoken
enc = tiktoken.encoding_for_model("gpt-4o-mini")
est_tokens = lambda s: len(enc.encode(s))
```

2. **预算要算「总账」而不只是上下文**。上下文 + 系统指令 + 问题 + **预留给输出的 `max_tokens`**，四者之和才不能超过模型窗口。只算上下文很容易在输出阶段被截断。

3. **跳过而非中断**。上面用 `continue` 语义（不 break）的好处是：如果第 4 段特别长放不下，但第 5、6 段较短，仍能塞进去，上下文利用率更高。

4. **如果经常触发大量丢弃，说明上游有问题**。要么 `chunk_size` 切得太大，要么 `top_k` 取得太多，要么该上重排先精筛。预算控制是最后一道防线，不该让它天天满负荷工作——真正的解法在检索侧。
</Answer>

## 小结

- RAG Prompt = 指令 + 编号上下文 + 问题 + 格式
- 按相关度从高到低截取，遵守 token 预算
- 超预算别硬塞，提示资料可能不完整
- 上下文可句子级筛选/摘要压缩；模板要配置化
