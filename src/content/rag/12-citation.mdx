# 生成与引用溯源（Citation）

RAG 的最大价值之一是**可溯源**：每个结论都能指回原始文档。如果用户问「凭什么这么说」，系统应能拿出依据。本章讲如何在生成阶段落地引用。

## 1. 为什么需要引用

- **可信度**：医生/法务/客服场景下，无来源的回答不可用
- **可纠错**：引用让人工快速核对，发现检索错误
- **合规**：金融、医疗等受监管行业常强制要求留痕

<Callout type="info" title="引用是 RAG 的「护城河」">
纯 LLM 回答无法证明来源，RAG 的引用能力正是它区别于「裸模型」的核心竞争力，也是企业敢用的前提。
</Callout>

## 2. 基础做法：编号 + 显式要求

在第 11 章已给上下文编号，这里在指令里强制引用：

```text
【资料】
[1] 年假规定：满一年享 5 天，满十年享 10 天。（员工手册.pdf 第 3 页）
[2] 病假需提供医院证明。（员工手册.pdf 第 5 页）

【问题】年假怎么算？
【回答】请仅在句末用 [n] 标注依据。
```

期望输出：满一年可享 5 天年假 [1]。

## 3. 解析与校验引用

让模型输出结构化 JSON，便于前端渲染可点击来源：

```python
import json
prompt = build_prompt(q, chunks) + "\n以 JSON 返回：{\"answer\": str, \"citations\": [int]}"
raw = llm(prompt)
obj = json.loads(raw)
cited = [chunks[i-1] for i in obj["citations"]]   # 回带真实来源
```

<Callout type="warn" title="模型会「编」引用编号">
LLM 可能引用不存在的 `[7]`。务必做**边界校验**：只接受 1..N 范围内的编号，超出的丢弃或提示模型重写。
</Callout>

## 4. 程序化强制溯源（更可靠）

不依赖模型自觉，而是用检索证据反查：

```python
def verify(answer, chunks, threshold=0.6):
    """检查 answer 中每个论断是否能在 chunks 找到支撑"""
    cited = []
    for c in chunks:
        # 用重叠度 / 重排分判断该段是否被用到
        if sentence_overlap(answer, c["text"]) > threshold:
            cited.append(c["metadata"])
    return cited
```

## 5. 前端展示建议

```json
{
  "answer": "满一年可享 5 天年假。",
  "citations": [
    {"source": "员工手册.pdf", "page": 3, "snippet": "满一年享 5 天"}
  ]
}
```

把 `snippet` 做成可点击气泡，用户一点就跳到原文位置。

<Callout type="tip" title="片段级引用优于文档级">
只标「来自员工手册.pdf」太粗，用户还要自己找。标到「页码 + 原句片段」才真正可用。这要求 chunk 的 `metadata` 里带 page 与精确定位（见第 3、8 章）。
</Callout>

**参考答案：**

**第一步：怎么诱发非法引用**

模型编造编号最常见的两个诱因：

1. **只给少量片段，却问一个需要多方面信息的问题**——模型觉得「这么复杂的问题应该有更多依据」，就凭空造出 `[4]`、`[5]`。
2. **问题问的内容资料里根本没有**——模型不愿说「不知道」，于是编个答案再随手贴个编号充门面。

```python
chunks = [
    {"text": "年假：满一年享 5 天。", "meta": {"source": "手册.pdf", "page": 3}},
    {"text": "病假需提供医院证明。", "meta": {"source": "手册.pdf", "page": 5}},
]   # 只有 2 段

question = "请详细说明年假、病假、婚假、产假、陪产假的天数与申请流程，并分别注明依据。"
answer = llm(build_prompt(question, chunks))
print(answer)
```

**典型的翻车输出**

```text
年假满一年可享 5 天 [1]。病假需提供二级以上医院证明 [2]。
婚假为 3 天 [3]，产假为 158 天 [4]，陪产假为 15 天 [5]。
申请均需提前 3 个工作日在 OA 提交 [6]。
```

`[3]`–`[6]` 全是编的，而且天数看起来很合理（是模型从训练数据里记住的通用法规），这种**「格式正确、编号越界、内容似是而非」的输出最危险**——用户看到方括号会下意识以为有据可查。

**第二步：边界校验与清洗**

```python
import re

CITE_RE = re.compile(r"\[(\d+)\]")

def sanitize_citations(answer: str, n_chunks: int):
    """过滤越界引用编号，返回 (清洗后答案, 合法编号集合, 非法编号集合)"""
    valid, invalid = set(), set()

    def _repl(m):
        idx = int(m.group(1))
        if 1 <= idx <= n_chunks:
            valid.add(idx)
            return m.group(0)          # 合法，原样保留
        invalid.add(idx)
        return ""                      # 非法，直接抹掉

    cleaned = CITE_RE.sub(_repl, answer)
    cleaned = re.sub(r"\s+([。，、；）])", r"\1", cleaned)   # 清理残留空格
    cleaned = re.sub(r"[ \t]{2,}", " ", cleaned)

    if invalid:
        cleaned += (f"\n\n> 注意：本回答中有 {len(invalid)} 处依据无法定位到已检索的资料"
                    f"（涉及编号 {sorted(invalid)}），相关内容未经核实，请谨慎采信。")
    return cleaned, valid, invalid


cleaned, valid, invalid = sanitize_citations(answer, len(chunks))
print(cleaned)
print(f"\n合法引用: {sorted(valid)}  非法引用: {sorted(invalid)}")
```

**清洗后输出**

```text
年假满一年可享 5 天 [1]。病假需提供二级以上医院证明 [2]。
婚假为 3 天，产假为 158 天，陪产假为 15 天。
申请均需提前 3 个工作日在 OA 提交。

> 注意：本回答中有 4 处依据无法定位到已检索的资料（涉及编号 [3, 4, 5, 6]），
> 相关内容未经核实，请谨慎采信。

合法引用: [1, 2]  非法引用: [3, 4, 5, 6]
```

**第三步：更进一步的三层防御**

只做正则过滤是**最低要求**，因为它只删掉了编号，那句编造的内容还留在答案里。生产系统建议叠加三层：

```python
def answer_with_guard(question, chunks, max_retry=1):
    n = len(chunks)

    for attempt in range(max_retry + 1):
        raw = llm(build_prompt(question, chunks))
        cleaned, valid, invalid = sanitize_citations(raw, n)

        # 第 1 层：无非法引用，直接通过
        if not invalid:
            break
        # 第 2 层：有非法引用则回炉重造一次，把错误明确告诉模型
        if attempt < max_retry:
            feedback = (f"你上次的回答引用了不存在的编号 {sorted(invalid)}。"
                        f"资料只有 [1] 到 [{n}]。请重写：只陈述资料中确实存在的内容，"
                        f"资料未覆盖的部分明确说明「资料中未提及」，不要编造。")
            question = f"{question}\n\n{feedback}"

    # 第 3 层：无句子级引用的论断，标记为待核实
    unsupported = [s for s in re.split(r"(?<=[。！？])", cleaned)
                   if s.strip() and not CITE_RE.search(s)
                   and not s.startswith(">")]
    return cleaned, sorted(valid), sorted(invalid), unsupported
```

**四条实践经验**

1. **校验必须在服务端做，不能只在前端隐藏。** 前端不渲染非法角标，但答案文本本身仍会被复制、被下游系统消费。清洗要发生在数据出口，而不是显示层。

2. **重试时要把错误明确回传给模型。** 只说「重写一次」效果很差；把「你引用了不存在的 `[4]`，资料只有 1–2 段」直白告诉它，纠正成功率高得多。这本质上是第 20 章 Self-RAG 反思机制的一个轻量版本。

3. **让 LLM 输出结构化 JSON 比解析纯文本更稳。** 用 `{"answer": ..., "citations": [1,2]}` 的结构，配合 JSON Schema / function calling 强制约束，能直接在 schema 层面限制取值范围，比事后正则可靠得多。

4. **根本解法在检索侧。** 模型编引用，很多时候是因为**检索确实没给够资料**。与其在生成后打补丁，不如：召回不足时（比如重排分数普遍偏低）直接回复「知识库中未找到相关资料」；或者把「资料只有 N 段，不要引用超过 N 的编号」写进系统指令，从源头降低发生率。

## 小结

- 引用让 RAG 输出可信、可纠错、合规
- 编号上下文 + 指令强制 [n] 是最简落地
- 必须校验引用编号，防止模型编造
- 片段级（页码+原句）引用最实用，需 metadata 支撑
