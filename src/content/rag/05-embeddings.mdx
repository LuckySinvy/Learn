# 向量与 Embedding 基础

RAG 的「检索」本质是**向量搜索**。要让计算机比较两段文字是否相关，得先把文字变成一串数字——也就是**向量（embedding）**。本章讲清楚向量空间与相似度，不依赖具体模型。

## 1. 什么是 Embedding

Embedding 是把离散对象（词、句子、文档）映射到一个**高维连续向量空间**的技术。语义相近的文本，在这个空间里距离更近。

```text
"猫喜欢吃鱼"   ──► [0.21, -0.83, 0.45, ..., 0.07]   (1536 维)
"猫咪爱吃鱼肉" ──► [0.19, -0.80, 0.48, ..., 0.09]   (距离很近)
"今天股票跌了" ──► [-0.62, 0.31, -0.11, ..., 0.55]  (距离很远)
```

注意：单看某一维的数字没有人类可解释的含义，意义只存在于**向量之间的相对位置**。

## 2. 向量空间直觉

可以把高维空间想象成一张「语义地图」：

- 每个点是一个文本片段
- 「意思接近」的文本聚成簇（如所有关于「退款政策」的片段离得近）
- 检索 = 把问题也投到这张地图，找离它最近的几个点

<Callout type="info" title="Embedding 是「意义的坐标」">
模型在训练时学到：同义、上下位、同主题的文本应靠近。这种几何结构让「算距离」等价于「算语义相似度」。
</Callout>

## 3. 相似度度量

检索时用一个分数衡量「多像」：

| 度量 | 公式直觉 | 取值 | 适用 |
|---|---|---|---|
| 余弦相似度 | 两向量夹角余弦 | [-1, 1]，越大越像 | 最常用，只看方向 |
| 点积 | 同方向且越长越大 | 任意 | 向量已归一化时等价余弦 |
| 欧氏距离 | 空间直线距离 | [0, ∞)，越小越像 | 少数场景 |

**余弦相似度**是 RAG 默认选择，因为它对向量「长度（文本长短）」不敏感，只关心方向。

```python
import numpy as np

def cosine(a, b):
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

q = np.array([0.21, -0.83, 0.45])
d = np.array([0.19, -0.80, 0.48])
print(cosine(q, d))   # 接近 1 → 高度相关
```

## 4. 维度（dimension）的意义

Embedding 维度常见 384 / 768 / 1024 / 1536：

- 维度越高，能编码的语义越细腻，但存储与计算成本上升
- 同一模型家族内，维度固定不可随意改
- 维度必须**检索端与文档端一致**，否则无法比较

<Callout type="warn" title="归一化让检索更快">
实际系统通常把向量归一化为单位长度，这样余弦相似度就等于点积，可用高效的近似最近邻（ANN）索引加速，详见第 7、8 章。
</Callout>

## 5. 一个向量搜索的最小演示

```python
# 假设已有问题向量 q_vec 和文档向量列表 doc_vecs
scores = [cosine(q_vec, dv) for dv in doc_vecs]
top_k = sorted(range(len(scores)), key=lambda i: scores[i], reverse=True)[:5]
```

<Callout type="tip" title="区分训练时与推理时">
Embedding 模型是「冻结」的：它不参与 LLM 的微调，只在你需要时把文本转成向量。选好一个模型后，离线入库和在线查询都调用它即可。
</Callout>

<Callout type="exercise" title="练习">
取三组句子（同义、反义、无关各一对），用任意 Embedding API 得到向量，亲手算余弦相似度，验证「同义 > 无关」。

<Answer>
**参考答案：**

```python
import numpy as np
from sentence_transformers import SentenceTransformer

model = SentenceTransformer("BAAI/bge-large-zh")

pairs = {
    "同义": ("公司规定满一年可以休五天年假",
             "工作满一年的员工享有五天带薪年休假"),
    "反义": ("这款手机的续航非常出色",
             "这款手机的续航非常糟糕"),
    "无关": ("今天北京下了一场大雪",
             "请问退款需要几个工作日到账"),
}

def cosine(a, b):
    return float(np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b)))

for label, (s1, s2) in pairs.items():
    v1, v2 = model.encode([s1, s2])
    print(f"{label}: {cosine(v1, v2):.4f}")
```

**典型输出与解读**

```text
同义: 0.9123     ← 最高，符合预期
反义: 0.8547     ← 出乎意料地高！
无关: 0.3012     ← 最低，符合预期
```

**核心结论一：同义 > 无关，验证通过。** 这说明 Embedding 确实把语义编码进了几何位置，「算距离」等价于「算相似度」，这是 RAG 检索能成立的基础。

**核心结论二（更重要）：反义句的相似度往往非常高，仅略低于同义句。** 这是很多人第一次做实验时最震惊的发现。

原因在于：Embedding 编码的是**主题相关性（topical similarity）**，而不是**逻辑真值**。「续航出色」和「续航糟糕」讨论的是同一个话题、同一个实体、同一个属性，只有一个极性词不同，在向量空间里自然离得很近。模型从来没被训练成「要把反义句推远」。

**这对 RAG 意味着什么？**

1. **检索会把「反例」一起召回。** 问「哪些产品支持退款」，很可能召回「本产品不支持退款」的条款——因为它们主题极其接近。这不是 bug，是 Embedding 的固有特性。
2. **别指望向量检索做逻辑判断。** 否定、条件、时效（「2023 年前的旧政策」vs「现行政策」）这类区分，向量做不了，要靠**元数据过滤**（第 8 章）或**重排**（第 10 章）兜底。
3. **反过来看这其实是好事**：把正反两面都召回来，交给 LLM 在完整上下文里判断，比只召回一面更安全。危险的是只召回了「不支持退款」却当成「支持」来答——所以 Prompt 里要强调「严格依据原文，注意否定表述」。

**可以再多做一步的实验**：把「同义」那组换成「同一句话的长短两个版本」，你会看到余弦相似度依然很高——这正印证了课文说的「余弦只看方向、不看长度」，文本长短不影响判断。
</Answer>
</Callout>

## 小结

- Embedding = 把文本映射为高维向量，语义相近则距离近
- 检索即「在向量空间找最近邻」
- 余弦相似度最常用，只看方向不看长度
- 维度需检索/文档两端一致，归一化可加速
