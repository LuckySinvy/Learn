# 项目实战：企业知识库问答

把前 16 章串起来，搭一个**端到端可运行**的企业知识库问答系统。目标是：丢进一堆内部文档，员工用自然语言提问，系统给出带引用的答案。

## 1. 系统目标与依赖

功能：多格式文档加载 → 切分 → 本地向量化 → 混合检索+重排 → 带引用生成。
依赖（pip）：

```bash

            rank_bm25 openai
```

## 2. 离线建库

```python
from langchain_community.document_loaders import DirectoryLoader
from langchain_text_splitters import RecursiveCharacterTextSplitter
from sentence_transformers import SentenceTransformer
import faiss, numpy as np, pickle

embedder = SentenceTransformer("BAAI/bge-large-zh")

# 1) 加载
loader = DirectoryLoader("./kb_docs", glob="**/*.{pdf,md,txt,docx}")
docs = loader.load()

# 2) 切分
splitter = RecursiveCharacterTextSplitter(chunk_size=500, chunk_overlap=80)
chunks = splitter.split_documents(docs)

# 3) 向量化 + 建 FAISS 索引
texts = [c.page_content for c in chunks]
metas = [c.metadata for c in chunks]
vecs = embedder.encode(texts, normalize_embeddings=True)
index = faiss.IndexFlatIP(vecs.shape[1])   # 归一化后内积=余弦
index.add(np.array(vecs, dtype="float32"))

# 4) 持久化
faiss.write_index(index, "kb.index")
pickle.dump({"texts": texts, "metas": metas}, open("kb.pkl", "wb"))
```

<Callout type="info" title="选用 FAISS + 本地模型">
本实战用 FAISS（轻量单机）和 bge 本地模型（数据不出网），适合中小企业知识库。规模上来后把 FAISS 换成 Qdrant/Milvus 即可，接口几乎不变。
</Callout>

## 3. 在线问答

```python
import openai, json
client = openai.OpenAI()

def answer(question, k=5):
    # 检索
    qv = embedder.encode([question], normalize_embeddings=True)
    D, I = index.search(np.array(qv, dtype="float32"), k=20)
    cand = [{"text": texts[i], "meta": metas[i]} for i in I[0]]

    # 组装上下文（带编号）
    ctx = "\n".join(
        f"[{i+1}] {c['text']}（来源：{c['meta'].get('source')}）"
        for i, c in enumerate(cand[:k])
    )
    prompt = f"""你是企业知识库助手，仅依据资料作答，未知则说不知道，句末标 [n]。
【资料】
{ctx}
【问题】{question}
【回答】"""

    resp = client.chat.completions.create(
        model="gpt-4o-mini", messages=[{"role": "user", "content": prompt}],
        max_tokens=512,
    )
    return resp.choices[0].message.content
```

## 4. 加重排（可选增强）

```python
from sentence_transformers import CrossEncoder
reranker = CrossEncoder("BAAI/bge-reranker-large")

def rerank(question, cand, k=5):
    pairs = [(question, c["text"]) for c in cand]
    scores = reranker.predict(pairs)
    return [cand[i] for i in np.argsort(scores)[::-1][:k]]
```

**常见的三种翻车与对应修法**

**翻车 1：只答了年假，完全没提病假**

原因是 `top_k=5` 全被「年假」相关片段占满了——因为问题里「年假」出现在前面，向量相似度更高。

修法是**多查询拆解**（第 14 章）：

```python
def multi_retrieve(question, k_each=3):
    sub_qs = llm(f"把下面问题拆成 2-3 个独立的检索子问题，每行一个：\n{question}")
    seen, merged = set(), []
    for sq in [s.strip() for s in sub_qs.split("\n") if s.strip()]:
        for c in retrieve(embed(sq), top_k=k_each):
            if c["id"] not in seen:
                seen.add(c["id"])
                merged.append(c)
    return merged      # 「年假流程」和「病假流程」各召回 3 段，均衡覆盖
```

**翻车 2：答案对，但只标了 [1]，另外两段没标**

原因是 Prompt 里的引用要求太弱。把指令写死：

```python
prompt = f"""你是企业知识库助手。严格遵守：
1. 仅依据【资料】作答，资料未提及的一律回答「资料中未说明」
2. **每一个事实性论断后面都必须标注来源编号**，如 [1]
3. 若答案涉及多个方面，分点作答，每点独立标注来源
4. 如果不同资料之间存在冲突，明确指出冲突并列出双方出处

【资料】
{ctx}
【问题】{question}
【回答】"""
```

**翻车 3：模型把两份文档的规定混为一谈**

比如把《员工手册》的年假天数说成是《考勤管理办法》里写的。这是引用错配，比不标引用更危险。

修法是在上下文里把来源标得更醒目，并要求模型逐条核对：

```python
ctx = "\n\n".join(
    f"[{i+1}] 来源：《{c['meta']['source']}》第 {c['meta'].get('page','?')} 页\n"
    f"内容：{c['text']}"
    for i, c in enumerate(chunks)
)
```

把「来源」放在内容**前面**且单独成行，比课文示例里追加在句尾的写法更不容易错配——模型读到内容时来源信息还在近处。

**跨文档场景特别要注意「文档冲突」**

真实企业文档里，新旧制度并存是常态。《员工手册》说年假 5 天，《2026 年假期调整通知》说改成 7 天，两段都会被召回。这时：

1. **元数据里必须有时间字段**，检索时优先取新的，或在上下文里按时间倒序排列。
2. **Prompt 里显式要求处理冲突**（上面第 4 条指令），让模型说「根据较新的《调整通知》为 7 天，原《员工手册》记载为 5 天」，而不是随机挑一个。
3. 这也反向说明**离线阶段的增量更新有多重要**——旧文档失效时若没及时从库里删掉，冲突会越积越多。

**最后：用 Ragas 量化，别只看一条**

单个问题答得漂亮可能是运气。凑 10 条跨文档问题跑一遍 `context_recall`（衡量「该召回的来源是否都召回了」），这个指标对跨文档场景最敏感——它低就说明多来源覆盖不足，该上多查询了。
