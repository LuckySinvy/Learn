# 核心概念

在动手搭建之前，先建立 Dify 的「词汇表」。理解了这几个核心对象，后续每章的界面操作都会变得理所当然。

## 1. 工作区（Workspace）

**工作区**是 Dify 里最高层的隔离单元，类似一个团队的「项目空间」。

- 每个工作区有独立的成员、应用、知识库与 API Key
- 一个账号可加入多个工作区，在不同团队间切换
- 企业版还支持把多个工作区归入「组织（Organization）」统一管理

<Callout type="info" title="数据边界">
工作区之间是数据隔离的。A 工作区的知识库、日志不会出现在 B 工作区，这保证了不同业务线互不干扰。
</Callout>

## 2. 应用（App）——四种类型

应用是你实际构建和发布的 AI 产物。Dify 提供四种应用形态：

| 类型 | 特点 | 典型场景 |
|---|---|---|
| **对话型（Chatbot）** | 多轮对话，带会话记忆 | 智能客服、咨询助手 |
| **文本生成（Completion）** | 单次生成，无多轮 | 文案、摘要、翻译批处理 |
| **工作流（Workflow）** | 节点画布编排固定流程 | 结构化、可控的自动化任务 |
| **Agent（智能体）** | 模型自主规划、调用工具 | 复杂任务、自主办事 |

<Callout type="tip" title="怎么选类型？">
流程固定、要可控 → 工作流；要模型自己想办法 → Agent；纯聊天 → 对话型；批量生成文本 → 文本生成。不确定时，先用对话型跑通，再视需要升级到工作流/Agent。
</Callout>

## 3. 应用的结构

一个对话型应用本质上由这几部分构成：

- **提示词（Prompt）**：系统提示、对话角色设定
- **上下文（Context）**：关联的知识库
- **变量（Variables）**：从用户/外部传入的参数
- **工具（Tools）**：可让模型调用的能力
- **模型（Model）**：底层大模型

这些在编排页（Orchestrate）里都能可视化配置，无需写代码。

## 4. 数据集（Dataset）——知识库的底座

**数据集**是知识库的存储单位，对应一组经过切片、向量化的文档。

- 一个知识库 = 一个或多个数据集的集合视图
- 数据集可关联给多个应用复用
- 支持增量更新与版本管理

```text
工作区 Workspace
 ├─ 应用 App（对话/文本/工作流/Agent）
 ├─ 知识库 Knowledge（关联 Dataset）
 └─ 工具 Tools / 插件 Plugins
```

## 5. 模型供应商与「模型」

Dify 把「模型」抽象成统一接口。你在「设置 → 模型供应商」接入 OpenAI、Azure、Ollama 等后，应用里就能像切下拉菜单一样切换模型。

<Callout type="exercise" title="动手认路">
登录控制台后，试着打开左侧「知识库」「工具」「设置 → 模型供应商」三个入口，先建立「它们分别管什么」的印象，后面章节会逐一填充内容。

<Answer>
**参考答案：**

**三个入口分别管什么**

| 入口 | 管什么 | 里面能看到 | 对应章节 |
|---|---|---|---|
| **知识库（Knowledge）** | 「模型知道什么」——你自己的资料 | 数据集列表、文档、片段数、索引状态、检索设置 | 第 4、5 章 |
| **工具（Tools）** | 「模型能做什么」——可调用的外部能力 | 内置工具（搜索、HTTP 请求、代码执行）、自定义 API 工具、插件市场 | 第 9 章 |
| **设置 → 模型供应商** | 「用哪个大脑」——底层模型接入 | 已接入的供应商、API Key、可用模型清单，以及系统默认模型（推理 / Embedding / Rerank / 语音） | 第 13 章 |

**一句话记忆法**

```text
模型供应商 = 大脑（能思考）
知识库     = 记忆（知道你的事）
工具       = 手脚（能干活）
应用 App   = 把三者组装起来的成品
```

**认路时值得留意的几个点**

- **模型供应商要先配**：没接入任何模型，创建应用时模型下拉框是空的，什么都跑不起来。所以实际操作顺序通常是「先配模型供应商 → 再建知识库 → 最后建应用」。
- **知识库里有两类模型依赖**：建库时要选 **Embedding 模型**（把文本变向量），检索时可选 **Rerank 模型**（精排）。这两个也都来自「模型供应商」——这就是三者的第一个联系。
- **工具是「工作区级」资源**：和知识库一样，配置一次可以被多个应用复用，不需要每个应用重新填一遍 API Key。
- **它们都不属于某个具体应用**：这三者都是工作区（Workspace）下的公共资源，应用只是「引用」它们。所以换工作区，这些东西都会变。

**自查小问题**

看完三个页面，试着回答：如果我想让助手「基于公司文档回答，并且能实时查天气」，我需要分别在哪几个入口做配置？

答案：模型供应商（接入推理模型 + Embedding 模型）→ 知识库（上传公司文档）→ 工具（启用天气类工具或配置自定义 API 工具）→ 最后在应用编排页把三者关联进去。
</Answer>
</Callout>

## 小结

- 工作区 = 团队隔离单元；应用是你要发布的 AI 产物
- 四种应用：对话型、文本生成、工作流、Agent，按需选择
- 数据集是知识库底座，可跨应用复用
- 模型被抽象成统一接口，切换无需改应用逻辑
