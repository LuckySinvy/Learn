# 高级提示词工程

第 7 章讲了提示词的基本骨架。当应用要进生产、要对接下游系统、要应对复杂问题时，**提示词工程（Prompt Engineering）** 决定了输出的上限与稳定性。本章讲四件进阶要事。

## 1. 思维链与推理框架

让模型「先想再答」能显著降低逻辑错误。经典做法是 Chain-of-Thought：要求模型分步推理，再给结论。

```text
请按以下步骤回答，不要跳步：
1. 先列出与问题相关的关键事实。
2. 指出其中存在的约束或矛盾。
3. 给出推理过程。
4. 输出最终结论（不超过 2 行）。
```

<Callout type="tip" title="复杂任务拆步骤">
涉及计算、排序、多条件判断的问题，强制「分步输出」比直接要答案更可靠。可以把中间步骤放到工作流的「变量」里，再喂给下一个节点。
</Callout>

## 2. 上下文压缩与成本控制

长对话会不断把历史塞进提示词，token 与延迟都涨。两种手段：

- **摘要压缩**：当上下文超过阈值，先用一个小模型把历史压缩成要点。
- **关键字段外提**：把用户资料、订单状态等结构化数据以变量形式注入，避免反复复述。

```yaml
# 上下文管理示意（伪配置）
context_strategy:
  max_tokens: 4000
  compress_when_exceeds: true
  compress_prompt: "将以上对话压缩为不超过 200 字的关键信息"
```

## 3. 结构化输出约束

要让下游程序解析，必须约束输出格式（如 JSON）。在提示词里明确 schema，并给出解析失败的兜底说明。

```text
只输出 JSON，不要任何解释，格式如下：
{
  "intent": "退款 | 咨询 | 投诉",
  "confidence": 0.0到1.0之间,
  "need_human": true或false
}
```

<Callout type="warn" title="别相信模型永远守格式">
即使写了「只输出 JSON」，模型偶尔仍会加一句前缀。生产解析前务必做容错：先剥离非 JSON 字符，再 json.loads，失败则走兜底分支。
</Callout>

## 4. 防幻觉与兜底策略

- 给知识库场景加「无依据则说不知道」的硬约束
- 用低温度（temperature 0.2–0.4）降低随机性
- 关键结论要求模型标注「来源片段编号」，便于溯源

<Callout type="exercise" title="动手做">
取一个你关心的复杂问题，分别用「直接回答」和「思维链四步法」各跑一次，对比答案的完整度与逻辑性，观察分步输出带来的差异。

<Answer>
**参考答案：**

**选题很关键**

思维链只在**需要多步推理**的问题上有效。选错题目会得出「CoT 没用」的错误结论：

| 适合验证 CoT 的问题 | 不适合的问题 |
|---|---|
| 多条件判断（满足 A 且 B，但 C 除外） | 「什么是 RAG？」——纯知识检索，一步就答完 |
| 涉及计算与比较 | 「今天天气怎么样」——靠工具不靠推理 |
| 需要权衡取舍的方案设计 | 「把这段翻译成英文」——转换类任务 |
| 有隐含矛盾需要识别的场景 | 简单事实问答 |

**示例题目**（含条件冲突，专门用来暴露差异）：

```text
客户 3 月 1 日下单企业版年付 12000 元，3 月 20 日申请退款。
我们的政策是：年付 30 天内无理由全额退款；
但若已使用超过 100 小时则按比例扣除；
且企业版客户享有额外 15 天延长期。
该客户已使用 150 小时。请问应退多少钱？
```

这题的陷阱在于：三条规则之间存在优先级关系，而题目没明说。

**版本 A：直接回答**

```text
提示词：
你是客服助手，请回答用户的退款金额问题。
```

典型输出：

```text
根据政策，客户在 30 天内申请退款，可以全额退款 12000 元。
```

**问题**：它抓住了第一条规则就收工了，完全忽略了「已使用 150 小时 > 100 小时」这个关键条件。这是 LLM 在多条件问题上最常见的失败模式——**过早收敛**。

**版本 B：思维链四步法**

```text
提示词：
你是客服助手。请严格按以下四步回答，不要跳步：

1. 【关键事实】列出与本问题相关的全部事实与规则，逐条编号。
2. 【约束与矛盾】指出其中存在的冲突、优先级不明或信息缺失之处。
3. 【推理过程】基于上述事实逐步推导，涉及计算时写出算式。
4. 【最终结论】不超过 2 行，直接给出金额与依据。若信息不足以确定，
   说明缺什么、需要向谁确认。
```

典型输出：

```text
【关键事实】
1. 订单：企业版年付，12000 元，下单日 3/1
2. 申请退款日：3/20，距下单 19 天
3. 规则 A：年付 30 天内无理由全额退款
4. 规则 B：已使用超 100 小时则按比例扣除
5. 规则 C：企业版额外享有 15 天延长期
6. 实际使用：150 小时

【约束与矛盾】
- 规则 A 与规则 B 冲突：19 天在 30 天内（满足 A），
  但使用 150 小时已超 100 小时（触发 B）。政策未说明谁优先。
- 规则 C 的「延长期」延长的是 30 天窗口（变为 45 天），
  但本例 19 天本就在窗口内，规则 C 不影响结论。
- 「按比例扣除」的计算基准未明确：按小时？按天数？
  年付总时长如何折算？

【推理过程】
- 时间窗口：19 天 < 30 天（+15 天延长期 = 45 天），窗口条件满足。
- 使用量：150 小时 > 100 小时，触发按比例扣除条款。
- 若按天数比例：已用 19 天 / 365 天 × 12000 ≈ 625 元
  应退 12000 − 625 = 11375 元
- 若按超额小时扣除：缺少单价标准，无法计算。

【最终结论】
信息不足，无法给出确定金额。若按天数计费，应退约 11375 元；
但需财务确认「按比例扣除」的计算口径与规则 A/B 的优先级。
```

**对比结论**

| 维度 | 直接回答 | 思维链四步法 |
|---|---|---|
| 条件覆盖 | 只用了 1 条规则 | 6 条事实全部列出 |
| 发现矛盾 | ❌ 完全没意识到 | ✅ 识别出规则冲突与口径缺失 |
| 结论正确性 | ❌ 错误（12000） | ✅ 诚实说明信息不足 |
| 可审计性 | 无法追溯 | 每一步都可检查 |
| 输出长度 | 约 30 字 | 约 400 字 |
| Token 消耗 | 基准 | 约 3–5 倍 |
| 延迟 | 基准 | 约 2–4 倍 |

**最重要的发现**：CoT 的收益不只是「答得更对」，而是**它会承认自己不知道**。直接回答模式下，模型倾向于给出一个自信的答案；分步模式强制它先审视条件，矛盾就藏不住了。在金额、医疗、法律这类高风险场景，这个特性比准确率提升更有价值。

**CoT 的代价与取舍**

```text
适合用 CoT：
  ✅ 高风险决策（涉及金额、合规、安全）
  ✅ 多条件、多步骤推理
  ✅ 需要人工复核推理过程的场景
  ✅ 离线批处理（不在乎延迟）

不适合用 CoT：
  ❌ 简单问答、闲聊（纯浪费 token）
  ❌ 强实时交互（用户等不起 4 倍延迟）
  ❌ 已用推理型模型（o 系列、DeepSeek-R1 等自带思考，
     再叠 CoT 反而可能干扰其内部推理）
```

最后一条现在尤其重要：**推理模型内置了思维链**，你再手动要求「分步思考」属于重复劳动，官方文档通常也建议对这类模型使用更简洁直接的提示词。

**生产环境的常见改良：隐藏中间过程**

用户不想看 400 字的推理过程，但你想要 CoT 的准确率。解决办法是在工作流里拆成两步：

```text
[Start] → [LLM-1: 四步 CoT 推理] → [LLM-2: 提炼最终结论]
                    ↓                        ↓
            （完整推理存日志）        （只把结论给用户）
```

LLM-2 的提示词：

```text
从以下分析中，只提取【最终结论】部分，
用不超过 2 句话面向客户表述，去掉所有分析过程与内部术语。

分析内容：
{{#llm1.text#}}
```

这样既保住了推理质量与可审计性（日志里有完整推理），用户看到的又是干净的结论。代价是多一次模型调用——可以用便宜的小模型做 LLM-2，成本增加有限。

**另一个变体：结构化 CoT**

如果下游要程序解析，可以把四步法改成 JSON 输出：

```text
只输出 JSON，不要任何解释：
{
  "facts": ["事实1", "事实2"],
  "conflicts": ["矛盾点1"],
  "reasoning": "推导过程",
  "conclusion": "最终结论",
  "confidence": 0.0到1.0之间的数字,
  "need_human": true或false
}
```

配合第 3 节的解析兜底，`need_human` 为 true 时自动转人工——这就把 CoT 的「发现矛盾」能力变成了可执行的业务逻辑。记得按正文那条 warn 做容错解析，模型偶尔还是会在 JSON 前加一句「好的，以下是分析结果：」。
</Answer>
</Callout>

## 小结

- 思维链（CoT）提升复杂任务准确率
- 用压缩与变量外提控制上下文成本
- 结构化输出需配解析兜底
- 防幻觉靠硬约束 + 低温度 + 来源标注；下一步深入知识库索引 →
