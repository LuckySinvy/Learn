# 项目实战：内部知识库助手

把前面学的串起来，做一个**企业内部知识库问答助手**：员工用自然语言提问，助手基于公司制度/手册回答，答有所据、可追溯。

## 1. 需求与目标

- 数据源：员工手册、IT 制度、报销流程等文档（Markdown/PDF）
- 要求：只基于资料回答，不知道就明说，不编造
- 形态：对话型 WebApp + 嵌入内网门户
- 合规：数据不出内网（自部署版）

## 2. 搭建步骤

**① 部署与模型（第 2、13 章）**
自部署 Dify，接入模型；Embedding 用中文模型（bge-large-zh）。

**② 建知识库（第 4、5 章）**
导入文档，自定义分段（按标题，最大 800 字，重叠 10%），混合检索 + Rerank。

```text
知识库「公司制度」
  文档：员工手册.pdf / IT规范.md / 报销流程.md
  分段：按标题切，800 字/段
  检索：混合检索，TopK=4，阈值=0.6，开启 Rerank
```

**③ 建对话型应用（第 6、7 章）**
写系统提示：

```text
你是公司内部的「制度助手」。
只依据提供的资料回答员工关于制度、流程的问题。
若资料中没有相关信息，请明确告知「未在资料中找到」，不要猜测。
回答尽量引用出处章节。
```

**④ 关联知识库与变量（第 8 章）**
加变量 `department`（下拉），提示词引用以适配不同部门话术。

**⑤ 调试与评估（第 15 章）**
用 10+ 真实问题测试，标注不理想回答，迭代提示词与检索参数。

<Callout type="tip" title="先「防幻觉」再「求好」">
第一步目标是「不知道就说不知道」，宁可少答不要乱答。稳定后再提升表达与覆盖率，比一开始就追求面面俱到更稳。
</Callout>

## 3. 发布与集成（第 14、16 章）

- 发布 WebApp，嵌入内网门户（iframe）
- 后端 API 供 HR 系统调用，Key 留在服务端
- 设「编辑者」维护知识库、「使用者」提问，权限分明

## 4. 持续运营

```text
员工提问 → 日志沉淀
  发现资料缺失 → 补文档 → 知识库增量更新
  发现答错 → 标注 → 优化提示词 → 评估回归
```

<Callout type="warn" title="知识库要有人养">
「建完就不管」的知识库会随制度变更而过时。指定 owner 定期更新文档，是助手长期好用的关键。
</Callout>

## 小结

- 串起部署、模型、知识库、提示词、变量、评估、发布全链路
- 关键取舍：先防幻觉，再提质量；检索参数按真实问题调
- 知识库需指定 owner 持续维护
