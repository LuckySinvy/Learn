# 知识库检索设置

文档切片入库只是第一步，**检索怎么召回**决定了模型拿到的是「干货」还是「噪音」。本章讲解把知识库接进应用时的关键检索参数。

## 1. 检索在 RAG 中的位置

```text
用户提问
  → 问题向量化（同一 embedding 模型）
  → 在知识库向量中找最相近的片段
  → 取出 TopK 个片段作为上下文
  → 拼进提示词交给大模型生成答案
```

检索质量直接决定答案上限：**召回不到 = 模型再强也答不对**。

## 2. 核心参数

在应用的「上下文 → 知识库 → 检索设置」中可调：

| 参数 | 含义 | 建议 |
|---|---|---|
| **TopK** | 召回的片段数量 | 3–5 常用；问答复杂可调到 6–8 |
| **相似度阈值** | 低于此分的片段不召回 | 0.5–0.7 起步，按命中率调整 |
| **检索模式** | 向量 / 全文 / 混合 | 见下文 |

```text
TopK = 4 且 阈值 = 0.6
  → 只把与问题相似度 ≥ 0.6 的前 4 段喂给模型
```

<Callout type="warn" title="阈值不是越高越好">
阈值设太高，容易「召回为空」，模型回答没依据；太低则混入无关片段，模型被带偏。先用中等阈值跑一批真实问题，看召回命中率再调。
</Callout>

## 3. 三种检索模式

- **向量检索（语义）**：按语义相似度召回，擅长「意思相近但用词不同」的问法。
- **全文检索（关键词）**：按关键词命中，适合专有名词、编号、精确匹配。
- **混合检索（Hybrid）**：向量 + 全文加权融合，兼顾语义与精确，推荐作为默认。

<Callout type="tip" title="混合检索是多数场景的最优解">
用户既可能问「怎么退款」（语义），也可能直接搜「订单号 ORD-12345」（关键词）。混合检索能同时覆盖，召回更稳。
</Callout>

## 4. 重排（Rerank）

开启 **Rerank 模型** 后，系统先粗召回一批候选，再用重排模型精排，把最相关的顶到前面。

```bash
# 在模型供应商中接入 rerank 模型（如 bge-reranker）
# 启用后检索流程变为：粗召回 TopK×N → 重排 → 取 TopK
```

重排能明显提升「相关片段排在最前」的概率，代价是额外一次模型调用延迟。

## 5. 效果验证方法

连上第 4 章建的两个知识库，在「调试与预览」里问同一批问题：

```text
问：「退货流程是怎样的？」
自动分段库召回：[片段A, 片段C, 片段B ...]
自定义分段库召回：[片段X, 片段Y ...]
对比：哪个更贴题、更完整？
```

<Callout type="exercise" title="调参练习">
固定问题集（≥10 条），分别测试「TopK=3/阈值0.5」与「TopK=5/阈值0.65/混合检索」两组设置，记录哪组答案更准，形成你的默认配置。

<Answer>
**参考答案：**

**第一步：构造问题集（关键，别省）**

问题集要覆盖不同「问法类型」，否则测不出两组配置的真实差异。建议 10–15 条，按下面配比：

| 类型 | 占比 | 示例 |
|---|---|---|
| 语义型（换个说法问同一件事） | 40% | 「东西不想要了怎么弄」（原文写的是「退货流程」） |
| 关键词型（专有名词、编号） | 25% | 「ORD-12345 这个订单号在哪查」 |
| 多跳型（答案分散在多个片段） | 20% | 「会员和非会员的退款时效分别是多久」 |
| 边界型（知识库里根本没有） | 15% | 「你们支持比特币支付吗」 |

**边界型必须有**：它专门用来检验「阈值是否有效拦住了无关召回」。理想表现是模型回答「资料中未提及」，而不是硬编一个答案。

**第二步：记录表（每题都填）**

```text
| 题号 | 问题 | 组A命中片段 | 组A答案对错 | 组B命中片段 | 组B答案对错 | 备注 |
|------|------|-------------|-------------|-------------|-------------|------|
| Q1   | ...  | 片段3,7,9   | 对          | 片段3,7,9,1,5 | 对        |      |
| Q2   | ...  | 无召回      | 错(编造)    | 片段12      | 对          | 关键词型 |
```

在「调试与预览」里，每次回答下方可以展开**引用与归属（Citations）**，能看到实际召回了哪些片段及其分数——这是判断「错在检索还是错在生成」的唯一依据。

**第三步：统计三个指标**

```text
召回命中率 = 召回结果中包含正确答案片段的题数 / 总题数
答案准确率 = 最终答案正确的题数 / 总题数
误答率     = 边界型问题中「硬编答案」的题数 / 边界型题数
```

**典型结果与解读**

| 现象 | 说明什么 | 怎么办 |
|---|---|---|
| A 组召回命中率低、经常「无召回」 | TopK 太小或阈值把正确片段挡在外面 | 提 TopK 或降阈值 |
| B 组召回率高但答案反而变差 | 召回太多噪音，模型被无关片段带偏 | 降 TopK，或开启 Rerank |
| 关键词型题目 A 组全挂、B 组正确 | 纯向量检索对专有名词/编号不敏感 | 这正是**混合检索**的价值 |
| 两组都答不对某几题 | 问题出在**切分**不在检索 | 回第 4 章调整分段策略 |
| 边界型题目被硬编答案 | 阈值过低 + 提示词没约束 | 提高阈值，并在提示词里加「资料中没有就说不知道」 |

**大多数场景的经验结论**

B 组（TopK=5 / 阈值 0.65 / 混合检索）通常**综合更优**，原因有二：

1. **混合检索是最大增益项**——它同时覆盖语义问法和关键词问法，单独开启带来的提升往往比调 TopK/阈值都大。
2. TopK=5 相比 3 多给模型一点冗余，配合 0.65 的阈值过滤，噪音并不会明显增加。

但**这不是标准答案**。真正的结论应该来自你自己的数据：如果你的文档片段很长（如 1500 字），TopK=5 可能直接撑爆上下文，那 TopK=3 反而更好。

**推荐的默认起点配置**

```yaml
检索模式: 混合检索（Hybrid）
  向量权重: 0.7
  关键词权重: 0.3
TopK: 5
相似度阈值: 0.6      # 开启 Rerank 时可适当降到 0.5，交给重排把关
Rerank 模型: bge-reranker-v2-m3   # 有条件就开，收益明显
```

配套的提示词约束（防止无召回时编造）：

```text
请严格根据【上下文】中的内容回答。
若上下文中没有相关信息，请直接回答「抱歉，我在资料中没有找到相关信息」，
不要根据常识或推测作答。
```

**进阶：调参顺序建议**

一次只改一个变量，按收益从大到小的顺序调：

1. **检索模式**（向量 → 混合）：收益最大
2. **是否开 Rerank**：收益次之，代价是延迟增加约 100–300ms
3. **TopK**：3 → 5 → 8，看答案是否变好
4. **相似度阈值**：最后微调，主要用于控制「宁缺毋滥」还是「宁滥毋缺」
</Answer>
</Callout>

## 小结

- 检索质量决定 RAG 答案上限
- TopK、相似度阈值需结合实际命中率调
- 混合检索 + Rerank 通常效果最佳
